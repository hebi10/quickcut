# QuickCut

**로그인·서버·DB 없이 실행되는 오프라인 Android 영상 편집기.**

스마트폰과 태블릿에서 영상을 선택해 필요한 장면만 편집하고 갤러리에 저장합니다. 디자인은 2026-10-08 확정한 다크 톤의 스마트폰 세로·가로 및 태블릿 가로 화면 시안을 기반으로 구현합니다.

> 구현 상태: **Android 0.4.9**. 고속 저장 추천 위치와 추가 삭제 길이를 표시하고, 사용자가 동의한 경우에만 적용합니다. [추천 위치 안내](docs/25_SAFE_CUT_SUGGESTIONS.md)를 참고하세요. 정확한 자르기 위치를 유지하며 H.264·H.265의 경계 부분을 처리하고 중간 구간을 복사합니다. 지원 소리 형식과 Main10 SDR·HDR10·HLG 범위를 넓히고, 고속 처리가 제한되는 사유를 표시합니다. 지원 조건과 기기별 검증 한계는 [0.4.8 고속 처리 확장](docs/24_BROADER_FAST_FORMATS.md), 엔진 구조는 [네이티브 부분 처리](docs/20_NATIVE_SMART_CUT.md), 고정 서명은 [배포 안내](docs/15_STABILITY_RELEASE.md)를 참고하세요. 모든 영상의 고속 처리를 보장하지 않으며, 사용자가 보고한 3시간 원본의 개별 오류는 아직 재현하지 못했습니다. 빌드·JVM 검사·Lint 및 Android 15 계측 검사는 [Actions](../../actions)에서 실행합니다.

## 사용 흐름

홈에서 **빠른 자르기(1개 영상)**, **일괄 편집(여러 영상)**, **상세 편집** 중 선택합니다.
앱이 마지막에 사용한 자르기 시간·음소거·저장 날짜 및 일괄 설정을 자동으로 기억합니다.
원본 휴지통/영구 삭제는 절대로 자동 적용하지 않으며 별도 승인이 필요합니다.

- 간편 자르기: 앞뒤 구간을 초 단위로 입력한 뒤 저장
- 일괄 편집: 파일 여러 개를 고르고 필요한 경우 템플릿·저장 옵션 펼치기
- 저장 직전: 고속 복사가 가능한지 검사하고, **재인코딩이 필요할 수 있으면 사용자 동의를 먼저 요청**
- 이전 편집: 원본 URI 접근이 유지된 경우 홈에서 **이전 편집 이어서 진행** 가능
- 일괄 복구: 완료된 출력은 확인 후 유지하고 남은 작업만 사용자가 다시 시작
- 저장 공간: 예상 용량과 임시파일·갤러리 복사에 필요한 여유 공간을 사전 검사
- 저장 결과: 길이·오디오·앞뒤 프레임·원본 날짜를 확인한 뒤 갤러리 공개
- 상세 편집: 1~16배 타임라인 확대 및 시작·종료 시각 직접 입력

### 일괄 편집 사용 방법

1. 시작 화면에서 **템플릿 · 일괄 편집**을 선택합니다.
2. `앞뒤 구간 삭제`, `처음 N초만 추출`, `마지막 N초만 추출`, `앞+뒤 연결` 중 작업 방식을 선택합니다.
3. 필요하면 음소거를 적용하고 이름을 입력해 **템플릿 저장**을 누릅니다.
4. **결과 저장 날짜**에서 `현재 날짜로 저장 (최신 영상)` 또는 `원본 날짜 유지`를 선택합니다.
5. 영상 여러 개를 추가하고 예상 결과 길이를 확인해 **일괄 편집 및 저장 시작**을 누릅니다.
6. 각 영상을 별도 MP4 파일로 저장하며 실패·건너뛴 항목은 이유를 표시합니다.
7. 원본 삭제를 선택하더라도 저장 완료 후 앱 확인 및 Android 시스템 승인이 필요합니다.

재시도나 영상 추가 시 **이미 저장한 결과물은 다시 내보내지 않습니다.** 삭제 요청은 **이번 실행에서 새로 저장에 성공한 원본만** 대상으로 하며, 대상 파일명 일부와 총건수를 보여준 후 별도 Android 승인을 요청합니다.

배치 작업은 다른 앱으로 이동하거나 화면을 꺼도 로컬 foreground service에서 순차 진행합니다. 프로세스가 종료되면 완료 파일을 검증하여 복구하고 남은 파일은 설정을 확인한 뒤 재시도합니다. 원본 처리 동의는 복구하지 않습니다. Android 15 이상 영상 처리 서비스는 시스템 실행 시간 제한을 따릅니다. 한 번에 최대 250개 영상, 템플릿 최대 30개로 제한합니다.

**날짜 유의사항:** Android 갤러리의 날짜 기준은 앱/기기마다 다릅니다. 원본 날짜는 촬영 메타데이터 우선이며, 없으면 원본 파일 수정 날짜를 사용합니다. 해당 정보 자체가 없거나 결과 날짜를 확인할 수 없으면 `원본 날짜 유지` 방식의 해당 파일은 저장하지 않습니다. <https://developer.android.com/reference/android/provider/MediaStore.MediaColumns>

### UI 배치

- **세로 스마트폰:** 상단 미리보기, 재생바, 타임라인, 하단 도구(자르기/분할/삭제/순서/음소거).
- **가로 스마트폰(사용 가능 높이 480dp 미만):** 미리보기 왼쪽, 도구 오른쪽, 축소 타임라인 하단.
- **넓은 태블릿 창(너비 840dp 이상):** 미리보기 왼쪽, 우측 속성 패널, 하단 전체 너비 타임라인.
- **그 외 중간 폭:** 세로 스택을 넓게 확장하고 영상 종횡비를 보존.
- 창의 현재 너비·높이 기준으로 분기합니다. 폴더블 힌지 회피는 후속 실기기 검증 항목입니다.

### 내보내기 정책

- 기본 고속 저장은 요청한 시작점과 안전한 키프레임이 정확히 맞을 때만 사용합니다. 조건이 맞지 않으면 사용자는 **정확한 위치로 자동 저장**(재인코딩 허용), 별도의 키프레임 조정 또는 취소를 선택합니다.
- 다중 영상도 고속 저장 가능/재인코딩 가능성/건너뛰기를 파일별로 사전 확인합니다. 다음 키프레임으로 옮기면 고속 저장 가능한 파일은 시작 위치와 추가 삭제 길이를 확인한 뒤 별도로 선택합니다.
- 끝부분을 자르지 않는 AVC/HEVC SDR 영상은 고속 저장 조건을 충족하면 B프레임도 압축 샘플 순서와 시각을 보존하며 고속 복사합니다. 선택한 키프레임 뒤에 그보다 이른 시각의 영상 프레임이 나오는 open-GOP는 제외하며, B프레임 영상의 끝부분 자르기는 정확한 위치 자동 저장에서 재인코딩이 필요할 수 있습니다.
- 사전 검사 이후 기기에서 고속 저장이 실패하면 허가 없이 전체 재인코딩하지 않습니다.


- 단일 H.264/HEVC SDR MP4 클립에서 삭제 시작점이 안전한 키프레임과 같으면 **MediaExtractor + MediaMuxer로 압축 샘플을 직접 복사**합니다. 기존 최대 50ms 시작 이동 허용은 제거했으며, 디코딩·재인코딩 없이 갤러리에 직접 기록합니다.
- 정확한 위치로 자동 저장을 선택하면 먼저 네이티브 엔진으로 경계만 처리하고 완전한 중간 GOP를 복사합니다. 영상 전체를 복사하고 소리만 AAC로 변환할 수도 있습니다. 지원 조건을 충족하지 못하면 제한 사유를 표시하고 **Media3 Transformer**로 저장합니다. 요청 시작점이 바뀌지 않는 경우에만 Media3 trim optimization을 시도합니다.
- 완료 화면과 일괄 기록에는 성공한 출력의 실제 처리 방식을 표시합니다. 요청 구간은 유지하지만 실제 출력은 원본의 프레임·오디오 샘플 단위 제약을 받습니다.
- 잘린 프레임을 MP4 edit list로 **보이지 않게만** 하는 위험한 저장 방식은 사용하지 않습니다.
- 고속 저장은 `IS_PENDING` 갤러리 항목에 직접 쓰고 길이·오디오 검증 후 공개합니다. Media3 경로에서는 앱 캐시의 임시 파일을 검증한 뒤 `Movies/QuickCut`으로 복사합니다.
- **기본값은 원본 유지**입니다. 저장 설정에서 휴지통 이동 또는 영구 삭제를 명시적으로 선택한 경우에만, 결과물 저장·재열기 확인 후 Android 시스템 승인을 요청합니다. 지원되지 않는 파일 제공자에서는 원본을 그대로 둡니다. 내보내기 속도는 편집 종류·코덱·기기 성능에 따라 다릅니다.
- 파일을 실제로 확인하기 전까지 절대 '무손실' 또는 '무조건 몇 초'를 보장하지 않습니다.

- 현재 미구현: 음악 삽입, 텍스트/자막, 크롭, 회전, 속도 변경, 필터, 전환 효과, 여러 프로젝트 관리. 실행 취소·다시 실행은 세션 메모리에만 유지됩니다.
- 단일 MP4 고속 저장에서는 중복 파일 복사를 제거했습니다. 복수 클립·원본 날짜 유지·기타 Media3 경로는 여전히 임시 파일 복사가 포함됩니다.
- 자르기는 **타임라인 핸들 드래그 + 범위 슬라이더**, 클립 재정렬은 **길게 눌러 한 칸 이동 + 이동 버튼**을 지원합니다. 여러 칸 연속 드래그는 후속 UX 개선 범위입니다.
- 폴더블 힌지와 태블릿 분할화면은 창 크기 적응 레이아웃을 적용했으나, 별도 WindowManager 기반 힌지 회피와 실기기 QA는 남았습니다.
- 우선순위: **실기기에서 1080p/H.264 자르기·분할·합치기 확인 → 오디오/비디오 싱크 검증 → 태블릿·폴더블 QA → 저장 속도 비교**.
- Android 15 자동 통합 테스트 4건(단일 구간 자르기, 중간 삭제 후 연결, 일부/전체 음소거)은 [±300ms 길이 검증까지 통과](https://github.com/hebi10/quickcut/actions/runs/37733293923)했습니다. 3초·320×240 H.264/AAC 샘플 기준으로 네 출력 파일의 재생시간은 목표와 일치했습니다.
- 에뮬레이터 테스트 로그와 저장 시간은 [09 에뮬레이터 검증 보고서](docs/09_EMULATOR_QA.md)에 기록했습니다.
- 테스트·남은 작업별 검증 시나리오: [구현 현황 및 실기기 QA](docs/08_IMPLEMENTATION_QA.md).

## 개인정보 및 저장

- 로그인, Firebase, 원격 서버, 분석 SDK, 광고가 없습니다.
- 일괄 템플릿·일괄 저장은 구현했지만 실제 고해상도·대량 배치 실기기 테스트가 남았습니다. Android 원본 삭제 시스템 승인도 기기별 확인이 필요합니다.
- `INTERNET` 권한과 전체 저장소 권한을 사용하지 않습니다.
- 사용자가 명시적으로 선택한 영상의 URI만 읽고 갤러리에 별도 MP4로 저장합니다.
- 편집 데이터는 메모리에서 관리하며, **앱 종료 시 저장된 간단한 편집 세션은 원본 접근 권한이 유효할 때 복원할 수 있습니다.** 영상 원본 전체를 앱 내부로 복사하는 완전한 프로젝트 보관 기능은 아닙니다.


### 개발판 APK 설치

0.4.1 배포 APK부터 보관한 고정 키로 서명합니다. 이후 업데이트도 같은 키를 사용해야 합니다. 기존 0.3.0/0.4.0 디버그 키는 확보하지 못했으므로 기존 설치본과의 덮어쓰기 호환을 보장하지 않습니다. 서명이 다른 앱을 삭제하면 앱 내부 설정·템플릿·편집 복구 기록이 초기화되므로 진행 중인 편집을 먼저 완료하세요. [서명 설정과 검증 범위](docs/15_STABILITY_RELEASE.md)에 세부 절차를 기록했습니다.
