# 02. 화면 및 UX 설계

- 상태: 기획 초안 v0.1
- 대상: Android 스마트폰, 세로 사용 우선 / 가로·폴더블 화면 반응형 대응 검토
- 디자인 원칙: **블랙·그레이 중심, 과도한 그림자·모서리 둥글림·장식·모션 배제**

## 1. 정보 구조

**화면 수를 최소화**한다.

1. **영상 선택** — 첫 실행 진입 화면 또는 즉시 시스템 영상 선택기
2. **편집기** — 미리보기, 타임라인, 도구, 저장 액션
3. **내보내기 상태** — 저장 진행, 취소, 오류
4. **저장 완료** — 결과 영상 확인, 갤러리 열기

회원가입·홈 피드·프로필·프로젝트 보관함 화면은 만들지 않는다.

## 2. 사용자 흐름

```text
앱 실행
  └─ 영상 선택
      ├─ 취소 → 이전 화면
      └─ 선택 완료 → 편집기
          ├─ 재생/일시정지/탐색
          ├─ 자르기/분할/삭제/클립 순서 변경/음소거
          ├─ 뒤로가기 → 편집 포기 확인 → 영상 선택
          └─ 저장
              ├─ 내보내기 진행 → 완료 → 갤러리 확인
              ├─ 취소 → 부분 파일 정리 → 편집기
              └─ 실패 → 원인 안내 → 편집기로 복귀
```

## 3. 편집기 레이아웃

**모바일 세로 화면**

```text
┌─────────────────────────────────┐
│  ← 편집                   저장  │
├─────────────────────────────────┤
│                                 │
│          영상 미리보기          │
│                                 │
│              ▶                  │
├─────────────────────────────────┤
│ 00:12.3                 01:30.0 │
│ ────────── ● ────────────────── │
├─────────────────────────────────┤
│ [클립1 ▣▣▣] [클립2 ▣▣▣] [클립3] │
│            ↑ 재생 헤드          │
├─────────────────────────────────┤
│ 자르기   분할   삭제   순서     │
│             음소거              │
└─────────────────────────────────┘
```

위 다이어그램은 배치 개념도이며 실제 화면 디자인이나 코드가 아니다.

### 레이아웃 원칙

- 상단은 뒤로가기와 **저장** 액션을 고정한다.
- 미리보기에서 재생·일시정지와 화면비를 명확히 표시한다.
- 타임라인은 가로 스크롤, 재생 헤드는 현재 위치를 표시한다.
- 선택된 클립만 구간 핸들 및 편집 도구를 활성화한다.
- 버튼 터치 영역은 44dp 이상을 원칙으로 한다.
- 작은 화면에서 타임라인을 무리하게 여러 트랙으로 쌓지 않는다.
- 시스템 상태 표시줄·하단 제스처 영역을 침범하지 않는다.
- 폴더블 펼침 화면에서는 미리보기와 타임라인의 여유 공간을 재배치한다.

## 4. 상호작용 상세

| 조작 | 기대 동작 | 오류/예외 |
| --- | --- | --- |
| 영상 선택 | 선택한 순서대로 타임라인 배치 | 열 수 없는 파일 안내 |
| 타임라인 탭 | 재생 위치 이동 | 영상 길이 밖으로 이동 불가 |
| 자르기 핸들 이동 | 시작/끝 지점과 예상 길이 즉시 표시 | 시작 ≥ 종료 금지 |
| 분할 | 재생 헤드 위치에서 클립 2개로 나눔 | 시작/끝 경계에서는 비활성화 |
| 삭제 | 선택 클립을 제거하고 빈 간격 없이 연결 | 모든 클립 삭제 시 빈 상태 안내 |
| 순서 변경 | 클립 길게 누르기·드래그 등 단순 조작 | 오디오·영상 순서 유지 |
| 음소거 | 해당 클립 원본 소리 제거 | 음성 없는 파일에서도 크래시 없음 |
| 저장 | 편집 내용 기준 내보내기 | 저장 불가 원인을 명시 |
| 뒤로가기 | 변경된 편집이 있으면 포기 여부 확인 | 실수로 편집 소실 방지 |

초기 MVP는 고급 효과 패널이 없는 단일 도구 모음을 사용한다. 2차 기능 추가 시에만 카테고리 구조를 확장한다.

## 5. 저장 화면

- 진행률을 숫자 또는 명확한 상태 문구로 표시한다. 정확한 퍼센트를 산출할 수 없는 단계는 '준비 중'으로 표현한다.
- 출력 파일명·저장 대상이 '갤러리'임을 안내한다.
- 저장 취소 시 결과 파일을 남기지 않는다(임시 데이터 정리).
- 성공 시 저장된 영상을 다시 열 수 있어야 한다.
- 저장 완료 전에는 성공으로 표시하지 않는다.
- 앱 전환·화면 회전·OS 프로세스 종료에 대한 동작은 실기기 검증 후 확정한다.

## 6. 오류·빈 상태

- 선택한 영상이 없을 때: **영상 선택** 버튼 제공
- 파일 접근 불가: **영상 다시 선택**
- 코덱/형식 미지원: **이 영상은 현재 지원하지 않습니다** + 형식 정보(확인 가능한 경우)
- 저장 공간 부족: 저장 공간 확보 후 재시도
- 인코딩 실패: 결과를 저장하지 않고 실패 이유 및 재시도 제공
- 예기치 않은 종료: 기존 원본 보존, 임시 파일 정리 가능하도록 설계

## 7. 후속 UI 확장(2차 이후)

- 오디오 트랙 1개 추가: 원본 볼륨, 배경음악
- 텍스트 트랙 1개 추가: 텍스트 내용·표시 구간·위치
- 회전·크롭·속도 설정은 **클립 선택 시** 관련 도구를 노출
- 복잡한 파라미터 조절과 다중 영상 레이어는 초기에는 제외

## 8. 접근성 및 QA

- TalkBack 레이블 제공: 재생/일시정지, 저장, 자르기 시작/끝, 클립 삭제
- 숫자 시간은 시각적으로 구분 가능한 글꼴과 충분한 대비 사용
- 기기 글자 크기 확대로 주요 버튼이나 편집 도구가 잘리지 않아야 함
- 미리보기의 화면비가 세로 영상·가로 영상에서 왜곡되지 않아야 함
- 빠른 드래그와 연속 탭에도 타임라인 상태가 일관되게 유지되어야 함
