# 03. 기술 및 내보내기 설계

- 상태: 기술 기획 초안 v0.1 / **구현 코드 없음**
- 목적: 빠르면서도 **정확하고 안전한 저장**을 위한 구현 기준 수립
- 원칙: 단순한 구조를 먼저 적용하고, 별도 엔진은 측정 결과가 필요할 때만 추가

## 1. 권장 기술 구성

| 구분 | 후보 | 선택 이유 |
| --- | --- | --- |
| OS | Android 전용 | 기기 내부에서 모든 편집·내보내기 수행 |
| 언어 | Kotlin | Android 미디어 API 직접 활용 |
| UI | Jetpack Compose | 단순 화면과 상태 기반 타임라인 |
| 재생/탐색 | AndroidX Media3 ExoPlayer | 로컬 영상 재생 |
| 복수 클립 미리보기 | Media3 CompositionPlayer 검토 | 편집 구성과 내보내기 데이터 일치 |
| 기본 내보내기 | Media3 Transformer | 클립, 제거, 효과, 변환 지원 |
| 고속 스트림 복사 | Media3 transmuxing 우선, 필요 시 MediaExtractor / MediaMuxer 검토 | 불필요한 비디오 재인코딩 최소화 |
| 갤러리 저장 | Android MediaStore | 사용자 기기 미디어 컬렉션 등록 |
| 영상 선택 | Android Photo Picker | 사용자가 선택한 파일에 한정 |
| 데이터 저장 | 앱 실행 중 메모리 | 초기 버전 별도 DB 불필요 |

- Gradle, Kotlin, Media3 등의 **구체적 버전은 구현 직전 호환성 검증 후 고정**한다.
- 최소 Android 버전은 API 26(Android 8) 등을 후보로 보고 실기기·라이브러리 요구 조건을 검토해 확정한다.
- FFmpeg나 추가 상용 라이브러리는 처음부터 넣지 않는다. 공식 API로 부족한 요구사항이 확인될 때만 비교한다.
- 비밀번호·토큰·API 키·로그인 서버·Firebase 설정은 존재하지 않는다.

## 2. 구성도

```text
[사용자 UI: Compose]
  ├─ 영상 선택: Photo Picker
  ├─ 미리보기: Player / CompositionPlayer
  ├─ 편집 상태: 클립 목록, 구간, 순서, 음소거 (메모리)
  └─ 저장 요청
        ↓
[내보내기 계획: Export Planner]
  ├─ 가능한 경우 압축 스트림 복사
  ├─ 가능한 경우 부분 최적화
  └─ 그 외 기본 재인코딩
        ↓
[내보내기 작업: Media3 Transformer 등]
        ↓
[결과 검증: 재생/길이/오디오/파일 존재]
        ↓
[Android MediaStore → 사용자 갤러리]
```

위 구조의 'Export Planner'는 설계상 역할 구분이다. 별도 모듈·추상화를 무조건 생성하자는 뜻은 아니다.

## 3. 내부 편집 데이터

MVP에서 관리할 최소 개념:

| 항목 | 내용 |
| --- | --- |
| 원본 참조 | 선택한 영상 URI (원본 자체는 수정하지 않음) |
| 클립 | 원본 참조, 소스 구간 시작/끝(ms), 현재 배치 순서 |
| 편집 옵션 | 클립 음소거 여부 |
| 재생 상태 | 현재 탐색 위치, 재생 여부, 선택된 클립 |
| 저장 상태 | 미시작 / 준비 / 실행 / 취소 / 성공 / 실패 |

편집 결과는 원본을 즉시 변경하는 대신 **클립/효과 지시의 목록**으로 유지하고, 저장 시 실제 파일을 출력한다.

## 4. 저장 경로 결정 규칙

### 4.1 빠른 복사 경로 (목표)

**가능 조건을 검사해 안전하다고 판단한 경우에만 사용**한다.

- 영상 픽셀을 변경하는 필터, 텍스트 삽입, 크롭 등 효과가 없어야 한다.
- 입력/출력 스트림·트랙·컨테이너 호환성이 확인되어야 한다.
- 시작·종료 지점, 키프레임 의존성, 오디오 동기화를 올바르게 처리할 수 있어야 한다.
- 여러 파일 연결 시 트랙 포맷·타임스탬프·코덱 파라미터 등을 검증해야 한다.
- 출력 파일의 제거된 구간이 실제로 제거되어야 한다.

**불확실할 때는 빠른 저장을 강행하지 않고 재인코딩 경로로 전환한다.**

### 4.2 트리밍 부분 최적화 (후보)

Media3 Transformer에는 시작 부분 트리밍에서 적은 구간만 재인코딩하는 실험적 최적화가 있다. 그러나 **단일 MP4 입력·효과 제한·인코더 호환성** 등의 조건이 있으며, 적용에 실패하면 일반 내보내기로 전환할 수 있다.

- 구현 시 SDK 문서 및 적용 가능 조건을 재확인한다.
- 결과가 실제로 최적화되었는지 내보내기 상태를 측정한다.
- 사용자는 처리 경로가 달라도 동일한 편집 결과를 받아야 한다.

### 4.3 일반 인코딩 경로

- 자막, 필터, 크롭, 속도 변경, 서로 다른 포맷의 복잡한 합성 등 영상 프레임 내용이 바뀌는 경우
- 하드웨어 디코더/인코더와 GPU를 가능한 경우 활용
- 인코딩이 필요한 경우 출력 포맷을 명시하고 사용자에게 품질·시간 차이를 안내
- 기기/코덱별 제약으로 하드웨어 가속이 실패할 수 있으며, 무조건 일정 시간 내 저장을 보장하지 않음

### 4.4 편집 종류별 기본 처리 판단

| 작업 | 이상적인 경로 | 주의사항 |
| --- | --- | --- |
| 단일 영상 자르기 | 가능한 경우 스트림 복사/부분 최적화 | 키프레임과 정확한 시작점 |
| 분할·중간 삭제 | 조건이 맞으면 복사 후 연결 | 각 구간 연결과 타임스탬프 |
| 같은 형식 영상 이어붙이기 | 포맷 호환 시 스트림 복사 검토 | 실제 코덱 파라미터 비교 |
| 음소거 | 영상 재인코딩 없이 오디오 트랙 제거 가능 | 오디오만 가진 파일 예외 |
| 배경음악/오디오 믹싱 | 오디오 처리는 필요, 영상은 조건부 복사 | 원본 소리와 싱크 |
| 텍스트·자막을 영상에 굽기 | 영상 인코딩 필요 | 프레임/위치 정확도 |
| 필터·크롭 | 영상 인코딩 필요 | HDR/색 영역 주의 |
| 속도 변경·전환 효과 | 재생시간·프레임 처리 필요 | 음성·프레임 싱크 |

### 4.5 사용하지 않을 최적화

**MP4 edit list로 잘린 앞부분을 감춘 채 파일 안에 인코딩된 데이터가 남는 방식은 기본 설계에서 사용하지 않는다.**

- 일부 플레이어는 edit list를 올바르게 해석하지 않을 수 있다.
- 사용자가 삭제했다고 믿은 장면이 결과 파일에 실제로 남을 수 있는 개인정보 위험이 있다.
- 빠르더라도 '삭제한 장면이 파일에서 제거됨'이라는 기대를 훼손하므로 기본 기능으로 채택하지 않는다.

## 5. 영상 형식·품질 정책

- 초기 목표 출력 형식: **MP4**. 실제 출력 코덱은 디바이스·입력·내보내기 경로와 지원 여부에 따라 결정.
- 재인코딩이 필요할 때 H.264/AVC + AAC 우선 검토(호환성 기준).
- 가능한 경우 원본 화면비·방향·해상도를 보존. 별도 이유 없이 해상도를 낮추지 않는다.
- HDR/HEVC/4K 영상은 구현 시 별도 호환성 테스트로 지원 범위를 확정한다.
- 재인코딩된 파일에 '무손실' 또는 '완전한 원본 화질' 표현을 사용하지 않는다.
- 단순 파일 크기 절감 때문에 비트레이트를 임의로 과도하게 낮추지 않는다.

## 6. 파일 저장과 권한

1. 영상 가져오기는 사용자가 명시적으로 선택한 미디어에만 접근하는 경로를 우선.
2. 임시 출력 또는 직접 출력 가능 여부를 API별로 확인; 빠른 저장을 위해 불필요한 파일 복사 최소화.
3. MediaStore에 성공적으로 등록된 파일만 갤러리에 노출.
4. 취소/실패 시 미완성 결과물·임시 파일 정리.
5. 동일 이름이 있을 때 기존 파일을 덮어쓰지 않음.
6. 원본의 다른 클립·메타데이터에서 민감 정보가 재노출되지 않는지 확인.
7. 선택한 URI 접근이 중단되면 필요한 경우 다시 선택하게 안내.

인터넷 권한이나 전체 저장소 접근 권한을 **관성적으로 추가하지 않는다.**

## 7. 고려할 장애와 제약

| 위험 | 대응 방향 |
| --- | --- |
| 키프레임 문제로 자른 앞부분이 더 재생됨 | 정확한 편집 경로로 폴백, 결과 샘플 검증 |
| 이어붙인 클립에서 음성 싱크 깨짐 | 타임스탬프·오디오 트랙 처리 검증 |
| 해상도/코덱 서로 다른 파일 결합 | 호환성 판단 후 필요 시 인코딩 |
| 출력 중 저장 공간 부족 | 사전 공간 안내 및 실패·임시 파일 정리 |
| 기기별 인코더 오류 | 지원 포맷 범위 관리 및 실패 상태 표시 |
| 영상 회전 정보 무시 | 출력 방향·화면비 재생 검증 |
| 4K/HDR 출력 품질 문제 | 테스트 통과 전 지원·품질 보장 금지 |
| 대용량 영상 저장 중 앱 전환 | 초기에는 전경 저장 우선, 이후 장시간 작업 정책 별도 설계 |
| 복잡한 전환 효과 | Media3 기본 Composition은 크로스페이드 미지원(기준일 문서), 별도 구현 검토 |
