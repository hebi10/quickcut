# 04. 개발 로드맵 및 품질 검증

- 상태: 기획 초안 v0.2
- 현재: **기획 문서 작성 단계. 코드·APK·실기기 테스트 미착수**
- 목표: 작게 시작하고 매 단계마다 실제 영상으로 저장 결과를 확인

## 1. 개발 마일스톤

| 단계 | 주요 산출물 | 다음 단계 진입 조건 |
| --- | --- | --- |
| M0. 기획 | 요구사항, UX, 저장 정책, 검증 계획 | 기능 우선순위·안전 원칙 문서화 |
| M1. 프로젝트 기반 | Android 네이티브 프로젝트, 기기 영상 선택·재생 | 앱 설치·선택·미리보기 성공 |
| M2. 단일 영상 편집 | 시작/끝 자르기, 음소거, MP4 출력, 진행/취소 | 출력 구간 정확도·갤러리 확인 |
| M3. 클립 편집 | 분할·삭제·클립 순서 변경·합치기 | 영상/음성 연속 재생·싱크 검증 |
| M4. 저장 최적화 | 빠른 경로 조건 검사, 인코딩 폴백, 측정 | 결과 정확성과 유의미한 성능 개선 확인 |
| M5. UX 안정화 | 오류/권한/기기 회전/저장 공간 처리, 타임라인 개선 | 1차 MVP 체크리스트 통과 |
| M6. 2차 기능 | BGM·볼륨·텍스트·크롭·회전·속도·되돌리기 | 개별 기능별 품질/호환성 검사 |
| M7. 후속 개선 | 필터, 전환, 프로젝트 복구 타당성 검토 | 실제 필요성과 성능 비용 검토 |

- M1~M5가 **1차 MVP**이며, 초기 목표는 2차 기능을 동시에 구현하는 것이 아님.
- 마일스톤은 선후 관계를 정의하며 일정·완료 보증이 아님.
- M0 이후 사용자가 개발 착수를 지시하기 전에는 코드 작성·설치·배포하지 않음.

## 2. 1차 MVP 완료 조건

### 사용 흐름
- [ ] 기기 갤러리에서 영상을 선택할 수 있다.
- [ ] 영상을 재생/일시정지하고 타임라인을 탐색할 수 있다.
- [ ] 시작점·종료점을 지정하고 실제 결과물이 해당 구간으로 저장된다.
- [ ] 분할, 삭제, 순서 변경 결과가 저장된 영상에 반영된다.
- [ ] 음소거 설정이 결과 영상에서 확인된다.
- [ ] 저장 성공/실패/취소 상태가 정확히 표시된다.
- [ ] 저장 성공 후 영상이 갤러리에서 재생된다.
- [ ] 원본 파일이 변경되지 않는다.
- [ ] 스마트폰/태블릿의 가로·세로 화면 및 창 크기 변경에서 저장·미리보기·타임라인이 정상 작동한다.
- [ ] 화면 회전 또는 분할화면 중에도 선택된 클립과 편집 구간이 유지된다.

### 안정성
- [ ] 빈 선택/0초 구간/모든 클립 삭제 상태에서 잘못된 저장을 방지한다.
- [ ] 읽기 권한 또는 URI 접근이 사라지면 예외를 처리한다.
- [ ] 파일 포맷 미지원 시 앱이 강제 종료되지 않는다.
- [ ] 저장 공간 부족 시 실패를 정확히 안내하고 미완성 파일을 정리한다.
- [ ] 내보내기 취소 시 일부 저장 파일이 최종 갤러리 파일로 노출되지 않는다.
- [ ] 세로/가로 영상의 회전 방향·화면비가 유지된다.
- [ ] 원본 음성과 편집 결과 음성의 싱크가 허용 범위 안에서 유지된다.
- [ ] 잘려 나간 민감 장면이 결과 파일에 숨겨진 상태로 남지 않는다.

## 3. 성능 측정 계획

**'몇 초 안에 저장'이라는 무조건적인 약속을 먼저 정하지 않는다.** 비교 가능한 실제 영상으로 측정한다.

### 측정 시나리오

| 케이스 | 입력 | 작업 | 목적 |
| --- | --- | --- | --- |
| P01 | 1080p, H.264/AAC, 1분 | 10초 구간 추출 | 고속 자르기 기준 |
| P02 | 1080p, H.264/AAC, 1분 | 중간 2구간 삭제 | 여러 컷 연결 성능 |
| P03 | 조건이 같은 영상 2개 | 이어붙이기 | 스트림 복사 가능성 |
| P04 | 1080p 영상 | 원본 오디오 제거 | 비디오 재인코딩 생략 확인 |
| P05 | 세로 영상 | 시작/끝 정확히 지정 | 세로 영상 메타데이터·절단 검증 |
| P06 | 4K 또는 HEVC 영상 | 짧게 자르기 | 호환성/폴백 확인(지원 여부 별도 결정) |
| P07 | 실제 기기 HDR 영상 | 짧게 자르기 | HDR 정보·톤 매핑의 예상치 못한 변경 여부 검토 |

### 측정 값

- 편집 후 **저장 버튼부터 완료 표시까지 실제 경과 시간**
- 출력 길이·파일 크기·영상 코덱·오디오 코덱·해상도·방향
- 사용된 저장 경로(복사/부분 인코딩/전체 인코딩/폴백)
- 재생 시작·종료 지점 오차
- 영상·오디오 동기화 이슈
- 실패·취소·재시도 결과

### 측정 방식

1. 동일 파일·기기·동일 편집 작업에서 비교한다.
2. 각 경로를 여러 번 반복하고 중앙값 등으로 비교한다(발열·캐시 영향 관찰).
3. 전체 재인코딩 대비 고속 경로의 개선량을 기록한다.
4. 정확성·재생 호환성을 통과한 결과만 속도 개선으로 인정한다.
5. 실험 결과가 없으면 '몇 배 빠름' 또는 '무손실'을 마케팅 문구로 사용하지 않는다.
6. 진단 로그는 로컬 개발용만 사용한다. 사용자 영상이나 편집 정보를 원격으로 보내지 않는다.

## 4. 호환성 테스트 매트릭스

반응형 UI/화면 상태의 구체적인 뷰포트·접근성 검사(R01~R15)는 [적응형 레이아웃 설계](06_ADAPTIVE_LAYOUT.md) 및 [화면 상세 설계](07_SCREEN_DETAIL.md)의 체크리스트를 따른다.

- Android 버전: 최소 버전 후보와 최신 주요 버전에서 검증
- 폼팩터: 일반 스마트폰·태블릿, 세로/가로 회전, 폴더블(가능한 경우), 화면 분할 및 창 크기 변경
- 영상: 가로·세로, 24/30/60fps, 무음 영상, VFR(가변 프레임레이트)
- 코덱: H.264/AAC를 우선, HEVC/HDR 등은 별도 확인
- 길이: 짧은 영상, 10분 이상, 대용량
- 저장 상황: 남은 공간 부족, 앱 전환, 화면 잠금, 취소, 연속 저장
- 경계값: 0초 근처 시작, 마지막 프레임 근처 종료, 키프레임이 아닌 위치 절단
- 조합: 같은 형식 여러 개, 다른 형식 여러 개, 음성 없는 클립 포함

기종에 따라 결과가 다를 수 있으므로 **에뮬레이터 통과만으로 영상 처리 완료를 선언하지 않는다.**

## 6. 작업 및 커밋 원칙

- 기획 승인 전: `README.md`와 `docs/` 문서만 수정.
- 코드 착수 후: 단계별로 작게 커밋하고 항상 실기기 테스트 결과를 남김.
- 큰 외부 의존성, FFmpeg, 자체 렌더 서버, DB 도입은 요구사항과 측정 결과로 정당화될 때만 결정.
- 다른 영상 편집기와 비교할 때 동영상 파일, 작업 조건, 기종, 인코딩 설정을 동일하게 맞춘다.
- '빠른 저장'보다 '사용자가 지정한 편집 결과가 정확히 저장됨'을 최우선 완료 조건으로 판단한다.
