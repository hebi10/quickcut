# 06. 반응형·적응형 레이아웃 설계

- 상태: 디자인 기획안 v0.1
- 목적: 폰·태블릿·폴더블·멀티윈도우에서 **편집 내용을 잃지 않고 사용 가능한 화면** 제공
- 기준: 실제 앱 창의 사용 가능 크기(window), 폭·높이·힌지/폴드 위치
- 관련: [디자인 시스템](05_DESIGN_SYSTEM.md) · [화면 상세 설계](07_SCREEN_DETAIL.md)

## 1. 기본 원칙

1. **기종/인치 기반 분기 금지:** 화면 크기는 '스마트폰이면 X', '태블릿이면 Y'로 판단하지 않는다.
2. 앱에서 사용할 수 있는 **현재 창 너비·높이(dp)**를 기준으로 레이아웃을 선택한다.
3. 창이 늘어나면 미리보기의 실제 크기와 도구 패널의 배치를 바꾼다. 동일한 스마트폰 레이아웃을 무작정 확대하지 않는다.
4. 화면 회전·폴더블 접기/펼치기·분할화면 전환 중에는 선택한 클립·재생 지점·트리밍 구간 등 **편집 세션 상태를 유지**한다.
5. 화면의 상태바·카메라 홀·제스처 영역·3버튼 네비게이션·키보드·힌지를 피해서 필수 컨트롤을 배치한다.
6. **영상 미리보기와 타임라인은 편집기의 핵심 기능**이므로 숨겨 놓고 메뉴를 여러 번 열어야 하지 않도록 한다.
7. 기능 우선순위: 저장 > 현재 편집 결과 확인 > 타임라인 > 선택 클립 도구 > 보조 정보.
8. 기기 방향을 강제 고정하지 않는다. Android 16(API 36) 대상 대형 화면의 방향·크기 강제 제약은 일반적으로 무시되므로 이에 의존하지 않는다.

## 2. 공식 Window Size Class 기준

### 너비(실제 앱 창)

| 클래스 | 창 너비 | 대표 시나리오 | 기본 QuickCut 구성 |
| --- | --- | --- | --- |
| Compact | 600dp 미만 | 스마트폰 세로, 좁은 분할창 | 단일 세로 스택 |
| Medium | 600dp 이상 ~ 840dp 미만 | 소형 태블릿 세로, 펼친 일부 폴더블 | 여유 있는 단일 스택 또는 얇은 도구 레일 |
| Expanded | 840dp 이상 ~ 1200dp 미만 | 태블릿 가로, 넓은 펼침화면 | 미리보기 + 도구 패널, 타임라인 별도 영역 |
| Large | 1200dp 이상 ~ 1600dp 미만 | 대형 태블릿·데스크톱 창 | 넓은 미리보기 + 제한폭 도구 패널 |
| Extra-large | 1600dp 이상 | 데스크톱 창 | 중심 콘텐츠 최대폭 관리, 불필요한 확장 방지 |

### 높이(너비와 독립적으로 판단)

| 클래스 | 창 높이 | QuickCut 대응 |
| --- | --- | --- |
| Compact | 480dp 미만 | 가로 스마트폰 등에 맞춘 압축 레이아웃 |
| Medium | 480dp 이상 ~ 900dp 미만 | 일반 스마트폰 세로·태블릿 가로 |
| Expanded | 900dp 이상 | 태블릿 세로 등에서 미리보기와 타임라인 높이 확대 |

**중요:** 너비가 840dp 이상이더라도 높이가 480dp 미만이면 일반 태블릿 3영역 레이아웃을 사용하지 않는다. 높이 부족이 우선이다.

> Window Size Class는 원칙적 레이아웃 전환 기준이다. 실제 배치·비율·패널 노출 여부는 창 여백, 시스템 인셋, 힌지 등을 반영한 **사용 가능 공간**으로 최종 결정한다.

## 3. 레이아웃 모드 선택(우선순위)

| 조건 | 모드 | 설명 |
| --- | --- | --- |
| 사용 가능 높이 < 480dp | ShortHeight | 가로 스마트폰/초저창 대응; 버튼·미리보기·타임라인 핵심만 |
| 폭 < 600dp, 높이 >= 480dp | PhoneStack | 상단 영상 / 중단 시간·타임라인 / 하단 도구 |
| 600dp <= 폭 < 840dp, 높이 >= 480dp | MediumStack | 프리뷰 확장, 상황에 따라 사이드 도구 레일 |
| 폭 >= 840dp, 높이 >= 480dp, 두 패널 공간 충분 | WideEditor | 상단 미리보기+우측 도구 / 하단 넓은 타임라인 |
| 넓지만 2패널 최소폭 충족 불가·가리는 힌지 | SafeStack | 크기가 큰 기기라도 단일 배치로 안전하게 폴백 |

- ShortHeight가 다른 모든 폭 조건보다 먼저 적용된다.
- 책처럼 접힌 듀얼 화면이나 폴더블의 힌지는 별도 세그먼트 공간을 확보한 뒤 해당 모드를 적용한다.
- 클립의 총 길이나 영상 비율 때문에 레이아웃 모드가 바뀌지는 않는다.

## 4. 스마트폰 세로 — PhoneStack

대표 검증용 창: 360×800dp 또는 393×852dp. **예시 수치이며 특정 기기 전용 UI가 아니다.**

~~~text
┌──────────────────────────────────┐
│ ←  편집                      저장 │  헤더: 약 56dp
├──────────────────────────────────┤
│                                  │
│            영상 미리보기          │
│           [Fit / 검은 여백]       │  나머지 높이를 우선 배정
│                                  │
├──────────────────────────────────┤
│     00:08.2    ▶    01:25.0      │  재생 영역
├──────────────────────────────────┤
│   | [클립 1] [클립 2] [클립 3] | │  타임라인(가로 스크롤)
│             ↑ 재생 헤드           │
├──────────────────────────────────┤
│ 자르기  분할  삭제  순서  음소거   │  도구: 최소 48dp 터치 영역
└──────────────────────────────────┘
    시스템 내비게이션 안전 여백
~~~

- 기본 가로 여백: 12~16dp.
- 타임라인은 높이 약 120~160dp 범위에서 조절(기기 높이에 비례).
- 도구 모음은 최대한 1줄로 제공하되 최소 48dp 터치 영역을 보장하지 못하면 가로 스크롤로 전환한다.
- 가로 스크롤 가능 상태는 부분 노출 또는 스크롤 안내로 인지 가능해야 한다.
- 세로 영상일 때 너무 높은 미리보기 때문에 타임라인이 화면 밖으로 밀리지 않도록 최대 높이를 제한한다.
- 영상/사진 선택은 시스템 Photo Picker를 사용하고 별도 복잡한 파일 탐색 UI를 만들지 않는다.

## 5. 스마트폰 가로/낮은 창 — ShortHeight

대표 검증용 창: 740×360dp 또는 850×390dp.

~~~text
┌─────────────────────────────────────────────────────┐
│ ← 편집                                         저장 │
├───────────────────────────────┬─────────────────────┤
│                               │ 자르기              │
│         영상 미리보기          │ 분할                │
│       [비율 유지, 최대화]      │ 삭제                │
│                               │ 순서 / 음소거       │
├───────────────────────────────┴─────────────────────┤
│ 00:08.2    ▶   01:25.0   | [클립1] [클립2] [클립3] | │
└─────────────────────────────────────────────────────┘
~~~

- 시간·타임라인을 결합한 **낮은 높이 전용 하단 패널**을 사용한다.
- 도구 목록은 오른쪽에 축약 표시하고 필요한 경우 자체 스크롤.
- 헤더 약 48dp, 타임라인 포함 하단 약 88~112dp를 목표로 하되 실제 창 높이에서 자동 조정.
- 실사용 높이가 360dp 이하 등 매우 작으면 도구를 한 행으로 축소하거나 '도구' 버튼을 눌러 패널을 열게 하는 안전 모드를 사용한다.
- 미리보기 최소 사용 가능 높이 확보가 어려우면 레이아웃을 스크롤 가능하게 하고 저장 버튼은 접근 가능한 곳에 유지한다.
- 필수 행동을 48dp 미만으로 축소하지 않는다.

## 6. 태블릿 세로/중간 폭 — MediumStack

대표 검증용 창: 700×1000dp 또는 800×1280dp.

~~~text
┌───────────────────────────────────────────────┐
│ ← 편집                                   저장 │
├───────────────────────────────────────────────┤
│                                               │
│             [넓은 영상 미리보기]               │
│                                               │
│                                               │
│              00:08.2   ▶   01:25.0            │
├───────────────────────────────────────────────┤
│   | [클립 1] [클립 2] [클립 3] [...]          │
│                   타임라인                    │
├───────────────────────────────────────────────┤
│ 자르기     분할     삭제     순서     음소거   │
└───────────────────────────────────────────────┘
~~~

- 높이가 충분하므로 미리보기·타임라인에 스마트폰보다 더 넓은 작업 공간을 제공.
- 영상 미리보기 컨텐츠는 **가로 최대폭 약 720dp**를 권장하고 가운데 정렬. 빈 공간에 UI를 무작정 늘리지 않는다.
- 창 폭이 약 720dp 이상이고 여유 공간이 있는 경우 도구를 얇은 보조 레일로 둘 수 있으나, 영상과 타임라인의 가독성이 감소하면 하단 도구 배치를 유지.
- 타임라인 높이 약 160~200dp 범위로 확장.
- 창 너비가 Medium이라도 높이가 480dp 미만이면 ShortHeight 적용.

## 7. 태블릿 가로/넓은 창 — WideEditor

대표 검증용 창: 1024×768dp, 1280×800dp, 1600×900dp.

~~~text
┌───────────────────────────────────────────────────────────────┐
│ ← 편집                                                   저장 │
├──────────────────────────────────────┬────────────────────────┤
│                                      │ 선택 클립: 02          │
│                                      │                        │
│            영상 미리보기             │ 자르기                 │
│            (비율 유지)               │ 분할                   │
│                                      │ 삭제                   │
│                ▶                     │ 순서 변경              │
│                                      │ 음소거                 │
│                                      │                        │
├──────────────────────────────────────┴────────────────────────┤
│ 00:08.2    ▶                                      01:25.0     │
│                                                               │
│ [클립1]    [클립2]       [클립3]        [클립4]                │
│                    타임라인(가로 스크롤)                      │
└───────────────────────────────────────────────────────────────┘
~~~

- 상단 작업 공간에 **미리보기(유연한 폭) + 도구 패널(권장 280~360dp)** 병렬 배치.
- 타임라인은 하단 전체 너비를 사용해 편집 정밀도를 확보. 권장 높이 약 180~240dp이나 창 높이에 따라 축소.
- 1200dp 이상에서는 미리보기의 컨텐츠 최대폭을 제한하고 도구 패널을 끝없이 넓히지 않는다.
- 도구 패널은 향후 2차 기능(음악, 텍스트, 크롭 등)을 넣을 때도 같은 구조를 유지할 수 있게 설계.
- **가로모드 태블릿이라고 하여 두 패널을 무조건 강제하지 않는다**. 창 높이와 힌지에 따라 폴백한다.

## 8. 폴더블/힌지/반개방

- 접힌 작은 외부 화면: PhoneStack/ShortHeight를 창 크기에 따라 적용.
- 펼친 내부 화면: MediumStack/WideEditor 중 실제 창 크기 기준 선택.
- **힌지/접힘 영역**이 실제로 가리는 공간(occluding feature)에는 텍스트, 저장 버튼, 재생 버튼, 트리밍 핸들을 배치하지 않는다.
- 힌지가 화면을 나눈다면 미리보기와 도구/타임라인을 가능한 범위에서 분리하되, 각 영역이 너무 좁으면 안전하게 한 패널씩 표시.
- 연속 조작하는 타임라인의 **드래그 핸들이 힌지를 가로질러야 하는 구성은 피한다**.
- 책처럼 세워 사용하는 자세에서는 힌지 양쪽에 각각 독립적인 주요 패널 배치 검토.
- 탁상형 반개방 시 영상 미리보기를 가림 없는 윗쪽, 타임라인/도구를 아래쪽에 배치할 수 있으나 구현은 WindowManager 폴딩 정보/실기기 확인 후 결정.
- 펼치기/접기 중 **선택 클립·재생 시간·트림 범위가 변경되지 않아야 한다**.

## 9. 분할 화면·창 크기 변경

- 창을 좁게 만들면 WideEditor → MediumStack → PhoneStack 순으로 재구성.
- 높이 480dp 미만으로 줄어들면 ShortHeight 모드 우선.
- 설정·모달은 창 밖으로 벗어나지 않아야 하며, 긴 설명/입력은 스크롤할 수 있게 한다.
- 텍스트 입력 키보드가 표시되면 해당 입력과 완료/취소 버튼이 가려지지 않게 IME insets 처리.
- 앱 창 리사이즈/회전 중 Player 재생 위치, 선택 클립, 커서·시간 범위를 보존.
- 최종 프로젝트 저장 기능은 MVP에 없지만 **회전/분할화면에 따른 Activity 재생성으로 편집 상태가 사라지는 것은 버그**로 본다.
- OS의 메모리 회수에 의한 프로세스 종료 뒤 완전 복구는 후속 범위로 별도 설명한다.

## 10. Edge-to-edge 및 시스템 영역

- Android 15(API 35) 이상을 대상으로 하면 edge-to-edge 동작에 따라 앱이 시스템 바 아래까지 그려질 수 있다.
- 시스템 status/navigation bar, display cutout, gesture, caption bar, IME insets를 반영한다.
- 영상 등 **비대화형 배경**은 시스템 바 뒤에 이어질 수 있지만 저장 버튼/핸들/확인·취소는 안전한 영역에만 배치.
- 상태바와 내비게이션바 아이콘의 대비를 보장한다.
- 3버튼 내비게이션과 제스처 내비게이션 양쪽에서 하단 도구가 겹치지 않는지 확인한다.
- 키보드가 활성화될 때 창 크기를 다시 평가한다.

## 11. 구현 시 기준 API (선정 후보)

- AndroidX Compose Material 3 Adaptive: **currentWindowAdaptiveInfoV2()** 및 WindowSizeClass, WindowPosture
- WindowManager: 폴딩/힌지 정보 및 창 레이아웃
- Compose: BoxWithConstraints 등 실제 사용 가능 폭·높이 측정, WindowInsets
- ViewModel: 구성 변경 시 편집 상태 보존; 프로세스 복구·프로젝트 저장은 별도 단계

버전별 제공 기능 및 호환성은 구현 시작 전 확인하고, 불필요한 추가 라이브러리는 도입하지 않는다.

### 통과 조건

- [ ] 영상 미리보기가 왜곡되지 않음
- [ ] 타임라인 및 자르기 핸들 조작 가능
- [ ] 저장·취소·뒤로가기 접근 가능
- [ ] 핵심 터치 대상 48×48dp 이상
- [ ] 불필요한 가로 오버플로/비의도적 컨텐츠 절단 없음
- [ ] 화면 회전·리사이즈·접기·펼치기 후 편집 상태 유지
- [ ] 힌지·시스템바·키보드가 주요 조작을 가리지 않음
- [ ] TalkBack·글꼴 확대 시 필수 기능 수행 가능
