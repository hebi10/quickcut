- 상태: 디자인 기획안 v0.1
- 단계: **코드 작성 전** / Android 네이티브 컴포넌트 미구현
- 관련 문서: [UX 흐름](02_UX_FLOW.md) · [디자인 시스템](05_DESIGN_SYSTEM.md) · [적응형 레이아웃](06_ADAPTIVE_LAYOUT.md)

## 1. 화면 목록

| 화면 | 목적 | 휴대전화 | 태블릿 | MVP |
| --- | --- | --- | --- | --- |

| B. 편집기 | 영상 편집 및 미리보기 | 세로 스택 / 짧은 높이 최적화 | 넓은 미리보기 + 도구 패널 / 하단 타임라인 | 포함 |

**앱 자체의 복잡한 메인 대시보드·회원 프로필·설정 탭은 만들지 않는다.**

## 2. A. 영상 선택 화면

목적: 사용자가 아무 설정 없이 편집할 영상을 가져온다.

~~~text
┌─────────────────────────────┐
│          QuickCut           │
│                             │
│                             │
│        [영상 선택]          │
│                             │
│   영상을 선택해 편집하세요   │
│                             │
└─────────────────────────────┘
~~~

- 화면 제목: **QuickCut**
- 주요 버튼: **영상 선택**
- 안내: **영상을 선택해 편집하세요**
- 버튼 탭: Android Photo Picker 등 시스템 영상 선택 UI 열기
- 선택 취소: 앱의 빈 시작 화면으로 복귀
- 1개 이상 선택을 지원하되, 처음 열기 경험은 하나의 버튼으로 유지
- 태블릿에서는 버튼과 안내문의 중앙 영역을 최대폭 약 420dp로 제한해 어색한 전체 너비 버튼을 방지
- 저장된 프로젝트 목록이나 동기화 안내 등은 표시하지 않음
- 영상이 없는 상황에서도 잘못된 권한 요청을 먼저 노출하지 않음

## 3. B. 편집기 화면

### 3.1 편집기 주요 영역

| 영역 | 목적 | 기본 행동 |
| --- | --- | --- |
| Header | 뒤로가기·화면 제목·저장 | 편집 포기 확인, 저장 |
| Preview | 실제 결과와 최대한 일치하는 비디오 출력 | 재생, 일시정지 |
| Playback | 현재 시간/전체 시간 | 탭/시킹 |
| Timeline | 클립 배치와 편집 범위 | 선택·탐색·자르기·순서 변경 |
| ToolDock | 선택 클립 작업 | 자르기·분할·삭제·순서·음소거 |
| Inspector(넓은 창) | 도구의 속성/세부 조작 | 선택 클립 시간·음소거 상태 등 |

태블릿에서도 새 기능을 임의로 추가하지 않고 **같은 기능을 보다 넓은 UI로 제공**한다.

### 3.2 Header

- 좌측: 뒤로가기(48×48dp) 및 '편집'
- 우측: **저장**(높이 48dp 이상), 영상이 없거나 내보내기가 진행 중이면 중복 실행 방지
- 앱 제목을 지나치게 크게 노출하지 않음
- 선택 클립명·길이 등 부가 정보가 필요하면 넓은 창에서는 별도 패널로 이동
- 가로로 매우 짧은 창에서는 높이를 줄이되 버튼 크기는 48dp 유지

### 3.3 Preview

- 원본 영상은 항상 종횡비 그대로 표시. 가로·세로 영상의 검은 여백은 정상 동작.
- 미리보기 누름: 재생/일시정지 전환, 필요하면 중앙 재생 아이콘 표시
- 재생 종료: 마지막 편집 프레임에서 정지, 재생 버튼으로 처음부터 시작 가능
- 로딩: 검은 배경과 상태 텍스트
- 재생 실패: 원인을 안내하고 다른 영상 선택 경로 제공
- 미리보기는 **최종 내보내기 가능한 편집 결과를 우선** 표현. 코덱 제약으로 차이가 예상되면 저장 전 사용자에게 안내
- 저장 중에는 잘못된 이중 조작을 방지

### 3.4 Timeline

**MVP는 주 영상 트랙 하나에 여러 클립을 나열한다.**

- 클립: 썸네일 띠 + 필요한 경우 길이 레이블
- 클립 탭: 클립 선택(선택 외곽선 표시)
- 시간 눈금자 탭/드래그: 재생 위치 이동
- 재생 헤드: 고정된 대비색 가이드, 현재 시간 표시. 화면 조건에 따라 중앙 고정 플레이헤드와 스크롤되는 타임라인 방식을 우선 검토
- 클립 시작/끝을 조절하는 자르기 핸들: 48dp 이상 히트 영역, 구간 길이·시간 값 표시
- 끝점을 시작점 이전으로 이동할 수 없음
- 0길이 선택, 모든 클립 삭제, 내보내기 불가능 구간이면 저장 버튼 비활성
- 매우 짧은 클립에서는 두 핸들 터치 영역이 겹칠 수 있으므로 상세 시간 조절 UI로 접근 가능해야 함
- 여러 클립을 길게 눌러 드래그하면 순서를 바꾸되, 접근성을 위해 '앞으로/뒤로 이동' 대체 조작 검토
- 타임라인 가로 스크롤과 클립 드래그 제스처를 명확히 구분(예: 짧게 드래그=스크롤, 길게 누르기=재정렬)
- 선택된 클립의 오디오를 음소거하면 타임라인 또는 도구 레이블에도 상태 반영

### 3.5 자르기 도구

- 선택 클립에 대해 **시작 시간·끝 시간·선택된 길이** 표시
- 기본 조작: 핸들 드래그
- 정밀 조작: 작은 단위로 시작/끝 값을 변경하는 접근 가능한 대안 제공(구체적 스텝 단위는 실제 프레임레이트 및 실기기 검증 후 확정)
- 프레임과 시간이 정확히 일치하지 않는 포맷에 대해 거짓 정밀도를 보장하지 않음
- 트리밍 동작은 원본을 변경하지 않고 클립 지시사항만 수정

### 3.6 분할·삭제·순서 변경·음소거

| 도구 | 활성 조건 | 동작 | 확인/피드백 |
| --- | --- | --- | --- |
| 자르기 | 클립 선택 | 해당 클립 양 끝점 조정 | 새 시작/끝 시간 표시 |
| 분할 | 헤드가 클립 내부에 있음 | 헤드 위치에서 2개 클립으로 분리 | 클립이 나뉜 것을 시각적으로 표시 |
| 삭제 | 클립 선택 | 선택 클립 제거 | 결과가 즉시 타임라인에 반영, MVP에서 즉시 실행 취소가 없으므로 오류 방지 UX 적용 |
| 순서 | 여러 클립 존재 | 선택 클립 위치 이동 | 편집 결과 재배치 |
| 음소거 | 클립 선택 | 원본 소리 켜기/끄기 | '켜짐/꺼짐' 상태 텍스트 |

**삭제 UX 판단:** MVP에 실행 취소가 없는 동안 실수로 클립을 제거하지 않도록 가벼운 확인 또는 직전 삭제 복원 기능 중 하나를 결정해야 한다. 완전한 실행 취소/재실행 시스템은 2차 범위로 유지.

## 4. C. 저장 진행 화면

### 4.1 시각 구성

~~~text
┌─────────────────────────────┐
│                             │
│       영상 저장 중           │
│                             │
│      ██████░░░░░░  50%      │
│                             │
│       갤러리에 저장합니다    │
│                             │
│          [취소]             │
│                             │
└─────────────────────────────┘
~~~

진행률 수치는 표시 예시다. 실제로 계산할 수 없는 처리 단계는 퍼센트 대신 상태 텍스트만 제공.

### 4.2 저장 진행 규칙

- 파일명은 간단하게, 기존 파일과 구분 가능한 자동 이름으로 생성.
- 사용자가 저장 버튼을 눌러야 최종 내보내기 시작.
- 진행 중 영상 선택이나 두 번째 저장 요청 방지.
- 취소 시 확인 후 내보내기를 중지하고 임시 파일 정리.
- 실패 시 실패 화면으로 전환하고 편집기 복귀 또는 재시도를 안내.
- 재인코딩을 수행하더라도 '항상 수초 내 완료'처럼 보장하지 않는 표현.
- 진행 메시지 예: '파일 준비 중', '영상 저장 중', '저장 확인 중'.
- 4K/긴 영상에서 오래 걸려도 UI가 멈춘 것처럼 보이지 않도록 업데이트.

### 4.3 반응형

- 스마트폰: 화면 가운데 상태 메시지·진행 표시·취소 버튼, 상하 여백 유연하게
- 태블릿: 상태 영역의 최대폭 약 480dp, 화면 가운데 배치
- 가로 짧은 창: 불필요한 아이콘·여백 축소, 상태·취소 버튼은 항상 접근 가능
- 폴더블: 힌지가 상태 텍스트나 취소 버튼을 가리지 않게 위치 선정

## 5. D. 저장 완료 화면

~~~text
┌─────────────────────────────┐
│                             │
│       저장 완료              │
│                             │
│     [영상 미리보기 영역]      │
│                             │
│     [갤러리에서 열기]         │
│     [새 영상 편집]           │
│                             │
└─────────────────────────────┘
~~~

- 타이틀: **저장 완료**
- 결과 미리보기 재생 가능하면 사용자에게 확인 수단 제공
- **갤러리에서 열기**: 내보낸 파일을 기기 영상 앱 등으로 열기
- **새 영상 편집**: 영상 선택 화면으로 복귀
- 기존 편집 내용을 자동 삭제하거나 원본 영상을 삭제하지 않음
- 태블릿에서도 완료 패널 자체의 최대폭 약 560dp를 유지

## 6. E. 확인·오류 UI

| 상태 | 메시지 원칙 | 주요 행동 |
| --- | --- | --- |
| 영상 불러오기 실패 | '이 영상을 열 수 없습니다' + 가능한 이유 | 영상 다시 선택 |
| 자르기 범위 오류 | '시작점이 끝점보다 앞서야 합니다' | 범위 수정 |
| 모두 삭제됨 | '편집할 영상이 없습니다' | 영상 추가 또는 이전으로 |
| 저장 공간 부족 | '저장 공간이 부족합니다' | 기기 저장 공간 확보 후 재시도 |
| 내보내기 실패 | '저장에 실패했습니다' + 확인 가능한 세부 이유 | 재시도 또는 편집 복귀 |
| 편집 포기 | '저장하지 않은 편집 내용이 사라집니다' | 계속 편집 / 나가기 |
| 저장 취소 | '저장을 취소하시겠습니까?' | 계속 저장 / 취소 |
| 입력 포맷 비호환 | '지원하지 않는 영상 형식입니다' | 영상 다시 선택 |

- 메시지는 **무엇이 잘못되었는지 + 사용자가 할 수 있는 다음 행동**을 포함.
- 경고나 오류를 색상만으로 구분하지 않는다.
- 삭제/나가기 같은 위험 동작에서 기본 포커스와 버튼 순서를 안전하게 설정.
- 모달 최대폭 제한 및 안전 영역 배치; 좁은 창에서는 본문 스크롤 가능.

## 7. 기기 환경별 화면 적용

| 요소 | 폰 세로 | 폰 가로/높이 부족 | 태블릿 세로 | 태블릿 가로 |
| --- | --- | --- | --- | --- |
| Header | 상단 고정 | 압축 높이 | 상단 고정 | 상단 고정 |
| Preview | 상단 중앙 | 좌측 주 영역 | 중앙 최대폭 제한 | 좌측 대형 영역 |
| Playback | 미리보기 하단 | 타임라인과 결합 | 미리보기 하단 | 타임라인 상단 |
| Timeline | 하단 가로 스크롤 | 하단 압축 영역 | 하단 넓은 영역 | 하단 전체 너비 |
| ToolDock | 맨 아래 1열/가로 스크롤 | 오른쪽 압축 도구 | 하단 또는 얇은 레일 | 우측 인스펙터 |
| Export UI | 중앙 상태 | 압축 중앙 상태 | 중앙 최대폭 | 중앙 최대폭 |

기종/물리 인치에 고정되는 설계가 아니라 **현재 창 크기에 따라** 해당 유형을 선택한다. 정확한 경계는 [06. 적응형 레이아웃](06_ADAPTIVE_LAYOUT.md)을 따른다.

## 8. 화면 회전·창 분할 중 상태 보존

**유지할 상태(구성 변경/Activity 재생성)**

- 현재 선택한 원본 영상 URI와 클립 목록
- 클립별 자르기 시작·끝, 순서, 음소거
- 선택된 클립
- 재생 위치 및 재생/일시정지 여부(정확한 재생 복원 정책은 Player 검증)
- 타임라인 줌/스크롤 등 화면 상태(가능한 범위)
- 저장 진행 상태 및 중복 작업 방지

**구현 주의**: 구성 변경 시 상태 복원과 앱 프로세스 종료 후 프로젝트 저장은 다른 요구사항이다. 후자는 MVP에 포함하지 않음.

## 9. 접근성·입력 UX

- 터치 대상은 **최소 48×48dp** 유지. 화면이 좁아도 버튼을 더 작게 하지 않는다.
- 타임라인에서 임의로 1px 손잡이처럼 보이는 조작도 실제 터치 영역과 TalkBack 이름 제공.
- 스크롤과 드래그는 동시에 사용 시 의도치 않은 편집을 만들지 않도록 명확히 구분.
- 세로 화면·가로 화면 모두 뒤로가기·저장 버튼을 찾아갈 수 있어야 함.
- Android 뒤로가기 및 제스처 내비게이션과 타임라인 좌우 제스처 충돌 방지.
- 200% 글꼴 확대에서 가로 배치 문구가 잘리면 여러 줄 배치/도구 가로 스크롤 허용.
- 하드웨어 키보드/태블릿 포인터 입력 시 포커스·클릭 동작을 보장; 추가 단축키는 후속 단계에서 검토.
- 키보드를 여는 정밀 시간 입력 등은 IME 인셋을 반영.

## 10. 디자인 승인 체크리스트

- [ ] 영상 선택→편집→저장까지 가입·설정 화면 없이 진행
- [ ] 스마트폰 320dp 너비에서도 필수 기능 접근 가능
- [ ] 가로 스마트폰 높이 360dp에서도 미리보기·타임라인·저장 동작 가능
- [ ] 태블릿에서 확장 공간을 활용하지만 요소가 끝없이 늘어나지 않음
- [ ] 폴더블 힌지에 핵심 컨트롤이 가려지지 않음
- [ ] 16:9, 9:16, 1:1 영상이 왜곡 없이 보임
- [ ] 회전/창 크기 변경 시 편집 세션 유지
- [ ] 저장 진행/오류/완료 화면이 모든 너비에서 읽기 편함
- [ ] TalkBack과 글꼴 확대 시 편집할 수 있음
- [ ] Shadow/Gradient/과도한 Border radius/장식 모션 사용하지 않음
- [ ] 앱 UI 시안·실제 개발 전 단계임을 문서에 명시

## 11. 차기 디자인 작업 범위

실제 UI 구현 요청이 있을 때 다음 순서로 진행:

1. PhoneStack 편집기(폰 세로)
2. ShortHeight(폰 가로)
3. WideEditor(태블릿 가로)
4. MediumStack(태블릿 세로)
5. 저장/오류/완료 화면 공통화
6. 폴더블/멀티윈도우의 실기기 조정

이 문서 자체는 UI 코드나 렌더링된 목업을 생성하지 않는다.
