## 2. 자동 검사

- GitHub Actions: `gradle --no-daemon :app:testDebugUnitTest :app:lintDebug :app:assembleDebug`
- 실패하면 APK 산출물 생성을 완료로 표시하지 않는다.
- 자동 단위 테스트는 현재 EditTimeline의 길이·분할·순서·음소거·경계조건, EditHistory의 이력 복원·상한·분기 등을 검사한다.
- Gradle/JVM에서 통과해도 Android 기기 디코더·인코더의 실제 동작을 보장하지 않는다.
- CI가 통과하면 Actions 실행 상세의 `quickcut-debug-apk` 아티팩트에서 개발용 APK를 받을 수 있다.

## 3. 실기기 기능 검사(미완료)

### 영상 가져오기·재생

- [ ] 1080p H.264/AAC 30fps 영상 1개 선택·미리보기 정상
- [ ] 1080p 영상을 여러 개 선택·추가하고 순서 정확히 반영
- [ ] 하나의 파일이 불러와지지 않을 때 나머지 영상은 계속 편집 가능
- [ ] 무음 영상, 짧은 영상, 세로 9:16 영상이 오류 없이 열림
- [ ] 앱이 저장소 전체 권한을 요구하지 않고 사용자가 선택한 URI만 사용
- [ ] 선택 클립을 바꾸거나 타임라인을 탐색할 때 현재 재생 위치 동기화

### 실제 편집 결과

- [ ] 시작/끝 트리밍으로 **키프레임이 아닌 위치**를 선택해 출력 구간 정확성 확인
- [ ] 타임라인 좌·우측 핸들로 자르기 동작 가능
- [ ] 구간을 분할한 후 중간 클립을 삭제하여 출력 영상에서 해당 구간 실제 제거
- [ ] 길게 눌러 이동, 앞뒤 이동 버튼으로 결과 순서가 맞음
- [ ] 음소거한 클립에서는 소리가 나오지 않음
- [ ] 오디오가 있는 클립과 없는 클립을 연결해 A/V 싱크 확인
- [ ] 원본 파일의 길이, 파일 내용, 갤러리에서 원본 존재 여부 변동 없음

### 저장 및 취소

- [ ] 저장 중 정확한 진행률이 있을 때만 백분율 표시
- [ ] 저장 완료 후 갤러리의 QuickCut 폴더에서 재생 가능
- [ ] 취소 버튼을 누르면 완료되지 않은 결과가 갤러리에 남지 않음
- [ ] 영상 처리 후 갤러리 등록 중에는 중복 취소가 불가능
- [ ] 남은 저장 공간이 적을 때 오류 후 임시/부분 파일 정리
- [ ] 긴 영상에서 백그라운드 전환·화면 잠금 동작 확인
- [ ] 한 번의 슬라이더/핸들 드래그가 실행 취소 1회로 복원되는지 확인
- [ ] 분할·삭제·이동·음소거 후 실행 취소/재실행이 정상 동작하는지 확인
- [ ] 제거한 프레임이 숨겨진 MP4 pre-roll 데이터로 결과 파일에 포함되지 않음

## 4. 화면·접근성 검사

- [ ] 360×800dp: 프리뷰·타임라인·하단 툴바 접근 가능
- [ ] 740×360dp: 폰 가로의 낮은 높이에서 주요 기능 사용 가능
- [ ] 800×1280dp: 태블릿 세로에서 영상 비율을 보존
- [ ] 1024×768dp: 태블릿 가로에서 좌측 프리뷰·우측 도구·하단 타임라인이 올바르게 표시
- [ ] 폴더블 펼침·접힘 시 선택된 구간 및 재생 위치 유지
- [ ] 분할 창 축소·확대 후 편집 세션 유지
- [ ] 시스템 상태바·내비게이션바·가상 키보드 겹침 없음
- [ ] TalkBack으로 재생, 저장, 자르기 슬라이더, 도구 버튼 조작
- [ ] 글자 크기 200%에서 버튼 문구 잘림·터치 충돌 없음

### 주의할 레이아웃

- 창 너비 600/840dp 경계에서 레이아웃 전환 여부 확인
- 높이 480dp 미만인 경우 별도 작은 높이 레이아웃 확인
- 폴더블 힌지가 주요 조작을 가리면 후속 WindowManager 기반 분리 레이아웃 필요

## 5. 속도 측정(미완료)

동일 기기, 동일 소스 영상, 동일 편집 작업에서 측정한다.

1. 1080p 1분 영상 중 10초만 추출
2. 1080p 1분 영상에서 중간 부분 두 군데 삭제
3. 같은 코덱/해상도인 영상 2개 합치기
4. 원본 음소거한 영상 저장

기록할 항목: 기종·Android 버전·코덱·해상도·원본 용량·출력 용량·실제 저장 경과 시간·오차·오디오 싱크·실패 여부.

Media3는 조건이 맞을 때 transmuxing/trim optimization을 적용하지만, **빠른 저장 및 원본 화질 유지가 모든 케이스에서 보장되지는 않는다**. 결과 검증을 통과한 작업만 성능 개선으로 인정한다.

## 6. 현재 알려진 한계

- 타임라인의 길게 누르기 재정렬은 **한 번에 한 칸 이동**으로 동작. 연속/다중 드래그는 후속.
- 구간 자르기 시작·종료 핸들은 직접 드래그 가능하나, 기종·글자 크기·TalkBack의 정밀 조작은 실기기 확인 필요.
- 클립의 썸네일 생성은 기기 메타데이터 디코딩 비용을 사용. 제한된 메모리 캐시를 적용.
- 저장 후 MediaStore 등록을 위해 임시 파일 복사가 발생하므로 최종 저장 시간에 디스크 I/O 비용이 포함된다.
- 실제 앱 프로세스 종료 시 미완성 프로젝트를 복구하지 않는다.
- 고정된 미리보기 렌더러와 장면 합성 지원 범위는 Media3 버전·기기 코덱에 따라 제한될 수 있다.

## 7. 후속 우선순위

1. **실기기 QA 결과 기반 결함 수정**: 파일 선택, 미리보기, 잘라내기, 저장, 음성 싱크
2. **태블릿·폴더블 QA**: 인셋, 재생 성능, 회전·크기 변경, 터치 영역
3. **저장 시간 벤치마크**: 빠른 저장이 실제로 유의미한지 측정
4. **2차 기능 개발 판단**: BGM·볼륨, 텍스트·자막, 회전·크롭·속도 조절, 실행 취소
5. 안정성 확보 후 단계적으로 배포/출시 계획 검토

위 미완료 항목은 앱 구현 성공과 별개로 평가해야 한다.

## 8. 에뮬레이터 실행 환경 참고

- 과거 GitHub Actions 실패 원인은 테스트 환경의 디스크 부족과 여러 줄 셸 반복문 실행 방식이었습니다.
- 대응: GitHub 실행 환경의 불필요한 도구를 정리하고, 테스트 명령을 `scripts/android-emulator-check.sh`에서 실행하도록 수정했습니다.
- Android 15(API 35) 에뮬레이터의 기본 영상 자르기, 클립 연결, 부분/전체 음소거 출력 4개 테스트가 모두 통과했습니다.
- 최신 테스트는 결과 파일 길이 오차를 ±300ms로 검사하며, 스마트폰·태블릿 크기별 시작 화면 스크린샷을 산출합니다. 최종 검증 상태는 [Actions 실행 기록](https://github.com/hebi10/quickcut/actions)으로 확인합니다.
- 계측 테스트 통과는 모든 기기·코덱·HDR·4K 동작을 보증하지 않습니다.
