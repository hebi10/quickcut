# 09. 에뮬레이터 영상 편집·저장 검증

- 기준: 2026-10-08
- 코드: [QuickCut `eb208eb58f66d09113ccdf7d43455b91a332515b`](https://github.com/hebi10/quickcut/commit/eb208eb58f66d09113ccdf7d43455b91a332515b)
- 자동 빌드: [GitHub Actions 성공](https://github.com/hebi10/quickcut/actions/runs/37733293971)
- 계측 테스트: [GitHub Actions 성공](https://github.com/hebi10/quickcut/actions/runs/37733293923)
- 환경: GitHub Ubuntu runner 위 Android 15(API 35) x86_64 에뮬레이터
- 입력: CI에서 FFmpeg로 생성한 **320×240, 30fps, H.264/AAC, 약 3초 영상**
- 테스트 범위: `VideoExportInstrumentedTest.kt`의 4개 케이스
- 결과: 계측 테스트 **4개 성공, 실패 0, 오류 0, 건너뜀 0**
- 길이 검사: 목표 시간 ±300ms 허용. 아래 케이스는 모든 결과가 목표와 동일한 밀리초로 보고됨.
- **이 데이터는 앱의 실제 기기 저장 속도나 상용 편집기 대비 성능을 의미하지 않습니다.**

| 시나리오 | 목표 길이 | 출력 길이 | 내보내기 경과 시간(에뮬레이터) | 결과 |
| --- | ---: | ---: | ---: | --- |
| 원본 0.5~2.5초 구간 자르기 | 2,000ms | 2,000ms | 8,747ms | 통과 |

경과 시간은 각 시나리오에 대해 **단 한 번 관측한 값**입니다. 파일/클립 종류, 재인코딩 여부, 캐시 상태, 에뮬레이터 부하가 달라 서로 다른 시나리오 간 속도를 비교해 결론을 내릴 수 없습니다.

## 2. 화면 검토

- 테스트 에뮬레이터에서 앱 시작 화면 실행 성공.
- 스마트폰 세로 및 태블릿 가로 크기(화면 크기 변경 후) 캡처 성공.
- 다크 테마 제목의 글자색이 검게 보이던 문제 수정 후 재확인.
- 이 캡처는 시작 화면만 검증합니다. **실제 편집기 화면의 세로/가로·태블릿·폴더블 검수는 미완료**입니다.
- 스크린샷은 계측 테스트 GitHub Actions의 `quickcut-emulator-start` 아티팩트에 보관합니다.

## 3. 미완료 검증

- 실제 Android 스마트폰 및 태블릿에서 설치·미리보기·편집·저장
- 1080p / 4K / HDR / HEVC / VFR 등 다양한 촬영 원본
- 시작/종료 프레임 오차 및 **삭제한 장면이 압축 데이터에 실제로 남지 않는지** 검증
- 오디오 샘플 싱크 및 개별 클립 구간에서 음소거 내용이 정확한지 확인
- 저장 중 앱 전환·화면 잠금·저장 공간 부족·프로세스 종료 시 복구
- 실제 기기별 저장 시간 반복 측정 및 기존 갤러리 앱과 비교
- 태블릿·폴더블의 편집기 화면과 접근성

## 4. 추후 실측 방식

같은 기기, 같은 원본, 같은 구간을 기준으로 첫 실행/재실행을 구분해 5회 이상 측정하고 중앙값을 기록합니다. 결과 시간은 다음을 구분합니다.

1. 영상 내보내기(Transformer) 시간
2. 검증 및 MediaStore 복사·등록 시간
3. 저장 버튼부터 완료 화면까지 사용자 체감 시간

비교할 때 출력 화질·코덱·재생시간이 동일한지 먼저 검사합니다. **무손실 또는 고속 저장을 모든 편집에 보장하지 않습니다.**
