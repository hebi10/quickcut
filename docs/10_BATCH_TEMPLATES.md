# 10. 영상 편집 템플릿과 일괄 처리 기획

- 기준일: 2026-10-08
- 상태: **기본 일괄 편집·템플릿 저장 구현, 실기기 검증 진행 중**
- 현재 구현: 단일 편집에서 저장 후 원본 처리 선택(`KEEP / TRASH / DELETE`) 코드 작성
- 본 문서는 구현된 기능과 다음 확장 항목을 함께 정리한 기준입니다.

## 1. 템플릿

템플릿은 원본 영상을 그대로 두고 처리 방법을 재사용하기 위한 **편집 규칙**이다.

- 템플릿 이름: 예) 앞뒤 3초 삭제
- 구간 방식: 앞 N초 삭제, 뒤 N초 삭제 / 앞 N초만 추출 / 뒤 N초만 추출 / 시작과 끝 각 N초를 연결
- 음소거: 적용 여부
- 내보내기: MP4, 입력 해상도 우선
- 짧은 영상: 설정한 편집 구간보다 짧으면 자동 건너뛰고 별도 표시
- 파일명: 원본을 덮어쓰지 않고 접미사 추가

## 2. 저장 후 원본 처리(중요)

| 선택 | 기본 | 의미 |
| --- | --- | --- |
| 원본 유지 | **기본값** | 원본 삭제 요청 자체를 만들지 않음 |
| 휴지통 이동 | 명시적 선택 | 편집 결과 확인 이후 Android 시스템 승인을 요청 |
| 영구 삭제 | 별도 명시적 선택 | 편집 결과 확인 이후 위험 안내와 Android 시스템 영구 삭제 승인을 요청 |

기본 정책:

1. 저장할 때마다 사용자에게 다시 확인한다. 템플릿에 과거의 삭제 설정이 있더라도 **새로운 일괄 실행은 원본 유지로 시작**한다.
2. 각 입력 영상의 결과 파일이 정상적으로 갤러리에 저장·검증된 경우에만 삭제 후보로 지정한다. **과거 실행에 성공한 원본은 이후 새 일괄 실행이나 실패 작업 재시도의 삭제 대상에 자동 포함하지 않는다.**
3. 배치 중 저장에 실패하거나 건너뛴 입력 파일은 **원본을 삭제하지 않는다**.
4. 전체 작업 종료 후 삭제 대상 원본의 파일명 일부와 전체 건수를 보여주고 사용자 확인을 받은 다음 Android OS 삭제 승인 화면을 사용한다.
5. 같은 원본이 여러 클립에 재사용되어도 **삭제 요청에는 한 번만 포함**한다.
6. 여러 원본이 하나의 출력으로 결합될 경우에도 해당 출력 저장 성공이 검증돼야 삭제 후보가 될 수 있다.
7. 파일 공급자가 Android MediaStore로 변환되지 않거나 권한이 없어 처리할 수 없다면 원본을 **그대로 유지**하고 이유를 표시한다.
8. 지원하지 않는 원본이 일부 섞였으면 그 원본을 몰래 무시하고 삭제 처리를 진행하지 않는다. 후보 목록을 다시 확인받는다.
9. Android 11 미만은 시스템 기반 일괄 삭제 승인을 지원하지 않는다. 임의로 다른 권한으로 원본을 삭제하지 않는다.
10. Android 16/API 36 대상 `MediaStore` 승인 요청당 2,000개 제한을 준수한다. 대량 작업에서는 건수별 승인 요청 또는 별도 안전 정책을 설계한다.
11. 원본 삭제는 사용자 확인 후에만 수행하고, 앱에서는 성공하지 않은 삭제를 성공했다고 표시하지 않는다.
12. 원본 처리 여부와 성공 결과물 수, 실패/건너뜀, 사용자가 취소한 승인 요청을 구분해서 표시한다.

## 3. 일괄 처리 큐

- `selected / ready / exporting / verifying / saved / failed / skipped` 상태를 영상별로 관리.
- 초기에는 발열과 디코더 충돌을 줄이기 위해 **순차 내보내기** 적용.
- 30개 원본 → 기본적으로 결과 MP4 30개를 각각 저장.
- 한 영상에서 문제가 발생해도 나머지는 계속 처리할 수 있도록 설계.
- 작업 완료 후 `30개 중 28개 완료, 2개 실패` 등 요약 제공.
- 결과 영상은 원본 파일과 분리해서 저장하고 파일명 충돌이 없도록 처리.
- 완료한 파일은 신규 영상 추가나 실패 항목 재시도 시 다시 렌더링하지 않는다.
- 중단/재시도/종료 복구를 도입할 때는 Room 등 **로컬 작업 상태 저장소** 도입 검토.
- 진행률과 저장 속도는 기기 및 코덱에 따라 차이가 있음.

## 4. 권장 사용 흐름

`템플릿 선택 → 영상 여러 개 선택 → 예상 결과 미리보기 → 저장 옵션(원본 유지 기본) → 일괄 내보내기 → 결과 검사 → 성공 원본만 삭제 후보 확인 → OS 승인 → 완료 요약`

특히 영구 삭제는 반복 템플릿에서 **자동으로 무인 실행하지 않는다**. 사용자가 파일과 건수를 확인해야 한다.

## 5. 기존 단일 편집과의 구분

- **현재 코드:** 일반 편집기 저장 시 `KEEP / TRASH / DELETE` 선택. 저장 완료 후 Android 시스템 삭제 요청 경로가 있으며, 지원하지 않는 URI는 원본을 보존.
- **구현:** 기기 로컬 템플릿 생성·목록·수정·삭제, 영상 여러 개 선택(최대 250개), 순차 렌더링, 영상별 저장·실패·건너뜀·재시도, 작업 완료 후 성공 원본만 시스템 삭제 승인 요청.
- **미구현:** 앱 프로세스 종료 뒤 배치 재개, 백그라운드 장기 실행 포그라운드 서비스, 템플릿 클라우드 동기화, 배치 프로젝트 영구 보관.
- 기존 단일 편집의 원본 처리 기능은 실기기에서 파일 선택 공급자·Android 버전에 따라 동작을 반드시 검사해야 함.
