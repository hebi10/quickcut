# QuickCut 0.3.0 UI/UX 및 저장 방식 개편

기준: 2026-10-14. 대상: `main`에 병합할 예정인 0.3.0 작업.

## 1. 화면별 사용자 흐름

- 홈: **마지막 사용 설정**, 빠른 자르기(영상 1개), 일괄 편집(여러 영상), 상세 편집, 저장된 편집 이어서 진행
- 간편 자르기: 영상 미리보기, 앞/뒤 삭제 시간 직접 입력, ±1초 버튼, 음소거, 상세 편집 전환, 하단 고정 저장
- 상세 편집: 기존 분할/삭제/재정렬/음소거 기능 유지, 초 단위 시작·종료 직접 입력, 타임라인 1~16배 확대
- 일괄 편집: 영상 선택 → 기존 설정 적용 → 간단한 자르기 옵션 → 저장 전 각 영상 처리 방식 확인 → 저장. 템플릿/날짜/원본 옵션은 필요할 때 펼친다.
- 저장 분석: 단일 영상은 가능한 경우 자동으로 고속 저장하고, 그렇지 않으면 **정밀 저장(재인코딩 허용)**, **키프레임 위치 조정(가능할 때만)**, 취소를 선택한다.
- 일괄 저장 분석: 고속 가능·재인코딩 가능성·건너뛰기 개수 및 파일명을 확인하고 **모든 영상 정밀 저장** 또는 **고속 가능한 영상만** 선택한다.
- 취소: 저장 도중 뒤로가거나 취소를 누르면 확인창을 거친다.

## 2. 영구 저장 정책

`QuickCutSettings`는 앱 전용 SharedPreferences에 저장한다.

| 값 | 앱 재실행 복원 |
| --- | --- |
| 빠른 자르기 앞/뒤 삭제 시간 | 예 |
| 빠른 자르기 음소거 | 예 |
| 마지막 저장 날짜 선택 | 예 |
| 일괄 편집 방식 및 앞/뒤 시간 | 예 |
| 일괄 음소거 및 템플릿 선택 ID | 예 |
| 저장된 템플릿 | 예, 기존 TemplateStore 유지 |
| 원본 휴지통 이동 / 영구 삭제 | **아니요, 항상 KEEP에서 시작** |

처음 선택한 영상에서 마지막 간편 설정이 원본 길이보다 길면 해당 범위를 강제로 적용하지 않고 원본 그대로 시작한다.

`EditorSessionStore`는 편집 클립·원본 URI·자르기 범위·음소거·재생 위치·간편/상세 모드를 로컬에 기록한다. 앱 재실행 시 **이전 편집 이어서 진행**을 누르면 원본 URI에 대한 접근 및 영상 길이를 확인해 복원한다. 접근할 수 없는 원본을 임의 파일로 대체하지 않으며 복원 실패를 알린다. 원본 파일 자체를 복사해 영구 보관하거나 프로젝트 서버에 업로드하지 않는다.

저장 완료 또는 사용자의 편집 포기 시 해당 임시 편집 세션은 삭제한다. 영상 파일은 별도 갤러리 저장 성공 여부와 원본 삭제 승인에 의해 관리된다.

## 3. 사전 저장 분석과 동의

`ExportPlanner.analyze()`는 실제 `FastMp4Trimmer.prepare()`와 같은 고속 경로 조건을 검사한다. 고속 가능 판정은 사전 예측이므로 실행 중 코덱, 스토리지, 기기 상태에 따라 다시 실패할 수 있다.

`ExportMode.FAST_ONLY`에서는 다음 조건을 지킨다.

1. 단일 클립·현재 날짜·지원 MP4 코덱·안전한 키프레임일 때만 스트림 복사를 시도한다.
2. 고속 경로가 불가능하거나 실행 중 고속 remux 처리에 문제가 발생하면 `ReencodeRequiredException`을 발생시킨다.
3. **사용자 허가 없이 Media3 Transformer 전체 인코딩으로 전환하지 않는다.**
4. 실패한 `IS_PENDING` 파일은 제거하고 원본은 그대로 둔다.

`ExportMode.ALLOW_REENCODE`는 사용자가 사전 검토 후 명시적으로 선택한 경우만 화면에서 전달한다. 이 모드에서는 고속 처리부터 시도하고 조건 불일치 시 기존 Media3 경로로 폴백할 수 있다. **정밀 저장에서 실제 얼마나 다시 인코딩되는지는 원본/기기/Media3에 따라 달라지므로 사전 확정해서 안내하지 않는다.**

키프레임 위치 조정 제안은 원래 사용자가 지정한 앞부분보다 더 많은 구간을 삭제할 수 있다. 변경 시 설명을 표시하고 먼저 편집 결과에 반영한 뒤 사용자가 다시 저장해야 한다. 원본 콘텐츠를 숨기기만 하는 MP4 edit list는 사용하지 않는다.

원본 날짜 유지 기능은 기존 경로를 사용하므로 0.3.0에서는 고속 remux가 지원되지 않는다. 재인코딩 가능성 안내를 통해 사용자에게 선택권을 준다.

## 4. 검증 조건

- 앱 재실행: 간편·일괄 편집 설정 및 저장 날짜의 자동 복원
- 템플릿: 이전에 저장된 템플릿이 삭제되거나 덮어써지지 않음
- 원본 삭제: 이전 세션에서 DELETE를 선택해도 새 세션에서는 KEEP
- 편집 복원: 유효 URI에서는 구간·선택·재생 위치 복원, 만료된 URI에서는 안전하게 실패
- 간편 자르기: 원본 1시간/앞 4초 삭제 수치 입력, 결과 길이 검증
- 사전 분석: 4초가 키프레임이면 고속 저장, 아니면 정밀 인코딩 허용 안내
- FAST_ONLY: 호환성 실패 시 Media3 무단 재인코딩 없음
- 일괄 편집: 대상별 사전 분류, 고속 가능 파일만 선택하면 나머지 원본/파일 미변경
- 취소: 진행 중 취소 확인 후 미완성 결과 삭제; 저장 완료분은 유지
- UI: 320dp 폰, 일반 스마트폰, 폴더블/태블릿, 가로/세로, 200% 글꼴 확대, TalkBack
- 성능: 실제 1시간 1080p 및 4K/HEVC/HDR 영상은 별도 **실기기 QA 필요**

Android CI 단위/계측 테스트는 회귀 검증에 유용하지만, 실제 1시간 영상의 속도를 확정하거나 모든 코덱/기기 호환성을 보장하지는 않는다.

## 5. 추후 확인

- 실기기에서 1시간 앞 4초 트림, 다양한 GOP 간격의 파일로 실제 고속 복사 vs Media3 처리 시간 비교
- 폴더블 내부·외부 및 가로 화면에서 간편 편집 터치 영역 확인
- 앱 강제 종료 시 직전 수백 ms 내 편집 상태 유실 여부와 갤러리 저장 공간 부족 경로
- 대량 배치 사전 검사에서 파일 수가 많을 경우 단계별 진행/중단 UX 검토
- 고급 편집에 음악, 텍스트, 효과를 추가할 때 저장 정책을 `ExportPlanner`를 통해 확장
