# 0.4.0 저장 안정화·백그라운드 작업

## 입력과 저장 일치

- 빠른 자르기와 상세 편집의 시간 입력을 공통 검증한다. 정확히 100ms를 남기는 범위도 저장한다.
- 잘못된 입력에서는 직접 저장, 저장 옵션, 저장 방식 선택에서 내보내기를 차단한다.
- 빠른 자르기 미리보기의 음소거와 출력 음소거가 일치한다. 플레이어 오류를 안내한다.
- 고속 저장 실패 후 정밀 저장 재시도에서는 같은 작업의 날짜·원본 처리 선택을 유지한다. 새 작업과 프로세스 복구에서 원본 처리 선택은 KEEP이다.
- 낮은 높이의 가로 화면에는 미리보기와 입력을 나란히 배치한다. 좁은 창과 큰 글꼴에서 입력 행을 나누고 스크롤을 제공한다.

## 출력과 용량

갤러리 공개 전 예상 길이와 실제 길이(허용 오차 300ms), 오디오 존재, 앞·뒤 프레임 읽기, 해당되는 원본 날짜를 검사한다. 고속 직접 저장과 Media3 경로에 같은 기준을 적용한다.

출력 생성 시 URI를 기록하고, 공개와 완료 상태 기록은 짧은 비취소 단계로 처리한다. 복사·검증 중 취소와 실패에서는 생성한 미완성 파일을 정리한다. 저장 성공이 확인된 원본만 별도 앱 확인과 Android 시스템 승인 대상이 된다.

원본 크기와 보존 구간을 바탕으로 출력 크기를 추정한다. 직접 고속 저장은 갤러리 공간, 일반 저장은 임시 파일과 갤러리 복사 공간을 확인한다. 같은 볼륨에서는 두 파일이 동시에 존재하는 비용을 포함한다. 추정치는 실제 비트레이트나 파일 시스템 쓰기 성공을 보장하지 않는다.

## 실행과 복구

사용자가 시작한 저장을 비공개 로컬 foreground service에서 진행한다. Android 15 이상에서는 mediaProcessing, 이전 버전에서는 dataSync를 사용한다. 알림과 화면에서 진행·중단을 제공하고 완료·실패·중단·시스템 시간 제한 때 서비스를 정리한다. 알림 권한을 허용하지 않아도 작업은 실행되지만 알림 창에 중단 버튼이 표시되지 않을 수 있다.

화면 회전과 앱 전환에서 모델과 작업을 유지한다. 일괄 목록·편집 계획·파일 상태·출력 URI·검증 기대값은 AtomicFile에 기기 내부 UTF-8 JSON으로 저장한다. 공개된 완료 파일은 다시 검증하여 유지하고, 기록 직전 프로세스가 종료된 출력도 유효하면 완료 상태로 채택한다. 미공개 파일만 정리하고 남은 작업은 자동 실행하지 않는다. 출력 접근이나 정리가 실패하면 URI를 유지하고 해당 파일의 재출력을 보류한다. 원본 접근을 갱신하여 같은 파일을 다시 선택하면 기존 미완료 행의 정보를 갱신한다. 앱 시작과 새 내보내기 전에 앱이 만든 중단된 캐시 MP4도 정리한다. 만료된 원본 접근 권한은 재선택을 안내한다.

단일 편집은 편집 내용 복원을 제공하며, 갤러리 공개 직후 프로세스가 종료된 단일 출력의 중복 저장 방지까지 보장하지 않는다. 일괄 출력의 URI·완료 기록 복구와 구분된다.

원본 휴지통·영구 삭제 동의는 복구 기록에서 제외한다. 인터넷 권한, 외부 서버, 분석·광고·원격 오류 수집은 추가하지 않았다.

독립 검토의 주요 발견 9개와 진행률 표시 1개를 보완했다. 시스템 중단은 사용자 취소와 구분하여 실제 작업을 취소하고, 완료 처리 이후 다음 파일을 시작하지 않는다. 삭제 실패나 출력 접근 실패에서는 URI를 유지하며 정리 확인 전 재출력을 보류한다. 날짜는 한 번 확인한 값을 출력과 복구 기록에 함께 사용한다. 목록 제거의 저장 실패는 기존 목록을 유지하면서 안내한다.

검사 화면에서 발견한 Pixel Launcher 응답 없음 때문에 첫 에뮬레이터 검사가 중단되었다. 테스트 시작 전에 해당 런처만 종료하도록 수정한 뒤 전체 52개 검사를 완료했다.

검토에서 범위를 구분한 항목: 단일 편집은 작업 내용을 복원하며 출력의 exactly-once 복구는 일괄 작업에 적용한다. 간편 편집에서 상세 편집으로 전환하면 잘못된 입력 초안은 버리고 마지막 유효 범위를 사용한다. 완료 파일만 있는 일괄 작업은 새 파일을 만들지 않는다. 기종·긴 영상 성능과 API 29/34/36 실기기 동작은 아래 QA로 남긴다.
