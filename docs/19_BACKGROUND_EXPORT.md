# 백그라운드 저장 유지

## 동작 범위

QuickCut의 단일·일괄 저장은 화면의 Compose 수명과 분리된 Application 소유 모델에서 실행한다. 홈 화면이나 다른 앱으로 이동해 Activity가 멈춰도 저장 coroutine을 취소하지 않는다. `ExportWorkService`가 foreground 알림과 `PARTIAL_WAKE_LOCK`을 유지하며, 실제 내보내기는 서비스 준비 확인 후 시작한다. 화면을 계속 켜 두는 것은 저장의 필수 조건이 아니다.

이는 기존 0.4.3에도 있는 기능이다. 새 엔진이나 무제한 백그라운드 실행 기능으로 표현하지 않는다.

## 확인된 종료 처리 문제

서비스의 작업 시작 명령 뒤에 알림의 중단 명령 또는 오래된 명령이 도착하면 Android의 최신 `startId`가 바뀐다. 기존 작업 감시자는 처음 작업을 시작한 `startId`로 `stopSelf(startId)`를 호출했다. 작업이 모두 끝나도 최신 명령 번호와 일치하지 않아 서비스 종료가 무시될 수 있었다. 기존 검사는 중단 callback을 직접 불러 실제 서비스 명령 전달을 검증하지 못했다.

수정은 작업 상태가 비었을 때 현재 서비스를 종료하는 데 한정한다. 오래된 작업의 명령은 진행 중인 새 작업을 중단하지 않아야 한다. 이는 완료 뒤 서비스 정리 문제이며, 일반적인 앱 전환이 저장을 중단시킨다는 증거는 아니다.

## 검증 기준

- 실제 서비스에 중단 명령을 전달한 뒤 작업 완료 시 서비스가 종료되는지 확인한다.
- 이전 작업의 중단 명령이 다음 작업을 취소하지 않으며, 다음 작업 완료 후 서비스가 종료되는지 확인한다.
- 실제 단일·일괄 영상 내보내기가 홈 화면·다른 앱·화면 꺼짐 상태에서 완료되는지 검사한다. 완료 후 Activity 재생성에서도 같은 모델과 결과가 유지되는지 확인한다.
- 완료 결과는 단순 화면 표시가 아니라 갤러리 게시 상태, 영상 길이, 오디오 존재로 확인한다.
- 완료·취소·시스템 종료 시 foreground 알림과 wake lock을 해제한다.

최종 실행 결과는 PR의 검증 기록에 남긴다. 짧은 API 35 에뮬레이터 검사는 모든 제조사 기기의 장시간 동작을 보장하지 않는다.

## 시스템 제한

Android 15 이상을 대상으로 하는 `mediaProcessing` foreground service는 백그라운드 실행 시간 제한을 받는다. 공식 문서는 24시간 동안 총 6시간을 허용하며, 사용자가 앱을 foreground로 가져오면 시간이 재설정된다고 설명한다. QuickCut은 시스템의 `onTimeout`을 받아 작업을 중단하고 서비스를 정리한다. 제한을 우회하거나 숨겨진 재시작을 하지 않는다.

사용자의 강제 종료, 운영체제의 프로세스 종료, 제조사 전원 관리 정책, 저장 공간·열·코덱 오류를 모두 막을 수는 없다. 일괄 저장의 기존 복구 기록은 완료 파일을 검증하고 미완료 파일을 사용자가 다시 시작할 수 있게 한다. 프로세스 종료 뒤 같은 파일을 중간 바이트부터 자동 재개한다고 약속하지 않는다.
