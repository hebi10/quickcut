# 일괄 자동 저장과 분·초 입력

## 사용 흐름

1. 여러 영상을 선택하고 삭제 또는 남기기 방식을 고른다.
2. `앞에서 삭제할 시간` / `뒤에서 삭제할 시간`을 분·초로 나누어 입력한다.
   구간 추출과 연결에서는 `처음부터 남길 시간` / `끝에서 남길 시간`으로 표시한다.
   예를 들어 1분 5.5초는 `분: 1`, `초: 5.5`다. 초는 0~59.999,
   한 구간은 최대 120분이며, 사용하지 않는 입력값은 편집 방식을 바꿔도 유지한다.
3. 설정 설명과 파일별 `원본 길이 → 저장 후 길이`를 확인한다.
   잘못된 입력은 바로 안내하고 저장 시작을 막는다.
4. `자동 저장 확인`에서 대상과 제외 사유를 확인한 후 `전체 자동 저장`을 누른다.
   짧은 원본, 읽을 수 없는 파일, 원본 날짜 정보 누락 등 실제 저장 불가 사유는
   계속 안내한다. 고속 처리 불가만으로 유효한 영상을 건너뛰지 않는다.

일괄 화면에서는 자르기 위치를 키프레임으로 옮기거나 고속 처리 가능한 파일만
선택하는 분기를 제공하지 않는다. 기존 명시적 `FAST_ONLY` API와 그 검증은 유지한다.
저장 후 원본 삭제·휴지통 이동은 기존과 같이 별도의 확인과 Android 승인이 필요하다.

## 저장 동작

안전한 단일 구간 직접 복사, 네이티브 부분 처리, Media3 정확한 저장 순서로 시도한다.
같은 원본의 앞·뒤 연결, 분할 후 연결도 네이티브 부분 처리 후보가 된다. 원본을
한 번 인덱싱하고 모든 구간의 경계·복사 시작점·최종 프레임 수를 검사한다.
조건이 맞지 않거나 결과 검증이 실패하면 공개 전에 일반 저장으로 전환한다.
소리가 있는 구간의 역순·중복·겹침도 부분 처리를 시도한다. 원본의 이전 시각으로
돌아갈 때 입력 오디오 디코더만 새로 시작하여 해당 구간의 소리를 유지한다.
영상 구간을 모두 복사할 수 있으면 소리만 다시 처리하며, 완료 화면에 실제
처리 방식을 표시한다. H.265 연결 지점이 앞 구간의 남은 프레임을 버리는 경우처럼
정확한 결과를 보장할 수 없는 조합은 일반 저장으로 전환한다.
취소는 새 저장 시도로 전환하지 않는다. 갤러리 공개는 최종 결과에 한 번만 수행한다.

모든 코덱·기기에서 무조건 빠른 처리나 저장 성공을 보장하지 않는다. 전체 처리가
필요한 영상은 더 오래 걸릴 수 있으며, 기기가 읽거나 인코딩할 수 없는 파일은
실패 사유를 알리고 다음 파일을 처리한다. 실제 처리 방식은 저장 완료 후 표시한다.

## 호환성과 검증

기존 설정·템플릿은 밀리초로 유지하며 데이터 형식을 변경하지 않는다. 기존 초 단위
문자열도 계속 읽는다. 분·초 입력은 십진수로 계산하여 `1.001초`가 `1.000초`로
잘리는 부동소수점 오차를 제거한다.

검증에는 분·초 범위와 정밀도, 기존 값 복원, 비활성 입력, 자동 저장 화면,
부분 처리와 전체 처리 혼합 일괄 저장, B 프레임의 구간 연결·반복·순서 변경,
압축 영상 데이터 복사 여부, 연결 지점의 디코딩·오디오, 취소·복구를 포함한다.
