# 고속 처리 제외 사유

0.4.7은 기존 저장 조건에서 탈락한 이유를 표시합니다. 지원 영상 범위와 정확한 자르기 조건은 유지합니다.

- 저장 중에는 확인된 원본 복사·부분 처리 제한을 표시합니다. 부분 처리 판별은 원본 검사 후에 끝날 수 있습니다.
- 완료 화면과 일괄 편집의 파일별 결과에는 실제 처리 방식과 해당 사유를 표시합니다.
- 부분 처리나 소리 처리로 성공하면 실패했던 대체 경로를 전체 재인코딩의 원인처럼 표시하지 않습니다.
- 저장 실패 시에는 오류와 이미 확인된 처리 제한을 함께 표시합니다.
- 일괄 편집 완료 기록에는 선택적 `copyReason`·`smartCutReason` 코드를 보관합니다. 기존 기록은 유지하며 사유가 없으면 기록 없음, 모르는 코드는 원인 확인 불가로 표시합니다.

원본 복사 검사의 키프레임·재생 순서·코덱·추가 트랙·회전 등의 사유를 전달합니다. 부분 처리 엔진에서는 색상 표본, 프레임 간격, 해상도, HDR, 오디오, 컨테이너, 구간 연결, 출력 검증 등의 실제 거절 지점에 안정적인 코드를 부여합니다. 엔진의 원시 오류와 파일 경로는 화면에 노출하지 않습니다.

JNI 성공은 기존 `[1, copiedPackets, encodedPackets]`, 취소는 `[-1, 0, 0]`입니다. 실패는 `[0, reasonCode, 0]`이며 0 또는 알려지지 않은 사유는 미확인으로 처리합니다. 진단 표시 실패가 저장 실패나 중복 저장으로 이어지지 않도록 UI 콜백 오류를 분리합니다.

이 변경으로 3시간 영상의 오류 원인이 해결되었다고 판단하지 않습니다. 해당 오류는 실제 문구 또는 원본으로 별도 확인해야 합니다.
