# QuickCut 15단계 — 해상도·FPS·압축 품질 내보내기

기준: 2026-11-08 · 앱 `0.4.20` · 14단계 PR #37과 독립된 단계별 작업.  
기획 원본: https://docs.google.com/document/d/1fTi_fx0g6CF6SwpRKjrlYdbK9Pp9oAqmSg6To4GkhfI/edit

## 기본 동작과 기존 기능 보존

- 기존 단일/상세 편집 저장 설정에서 '내보내기 화질'을 추가한다.
- **자동(해상도/FPS/압축 모두 자동)**: 현재 `ExportPlanner` 및 `VideoExporter`의 고속 원본 복사·네이티브 부분 처리·Media3 폴백을 **변경하지 않는다**.
- 사용자가 하나라도 수동 옵션을 선택하면 **명시적 재인코딩 승인**을 받아 Media3 Composer/Transformer로 저장한다.
- 기존 저장 날짜, 원본 유지/휴지통/삭제 승인, 단일 저장 복구 저널·기기 저장소 검사 및 갤러리 검증을 그대로 이용한다.
- 이 단계는 일괄 편집/프리셋의 필드를 변경하지 않는다. 일괄 편집의 저장 값은 기존대로 유지된다.

## 신규 화면

- 해상도 선택: 자동, 720p, 1080p, 4K. 가로/세로 영상 모두 짧은 변을 기준으로 처리하며 영상 종횡비를 유지한다.
- FPS 선택: 원본 유지, 30, 60. 프레임이 부족한 원본은 인위적으로 늘리지 않고, 원본 프레임레이트를 확인할 수 없거나 더 낮으면 수동 FPS를 제한한다.
- 압축 품질: 자동, 낮음, 보통, 높음. 화면 해상도/목표 FPS에 따른 비트레이트를 Media3의 H.264 인코더 설정으로 전달한다.
- 예상 용량: 영상 길이·비트레이트·오디오 용량을 고려한 대략적인 크기만 표시. 실제 크기는 다를 수 있다.
- 지원 불가: 원본보다 높은 해상도, 기기에서 지원하지 않는 H.264 해상도/FPS, 원본 정보 미확인, HDR, 서로 다른 입력 화면비 등은 이유를 표시하고 저장을 비활성화한다.
- 확인 버튼: 자동일 때 기존 저장 흐름, 수동일 때 재인코딩 확인 모달 이후 저장. 취소 시 임시 설정 폐기.

## 실제 인코딩 경로

- `ExportQualityPolicy`: 순수 Kotlin으로 포맷 유효성·기본/수동 설정·목표 비트레이트 및 용량을 계산한다.
- `ExportQualityInspector`: 원본 스트림 해상도/FPS/HDR 및 기기 H.264 인코더 지원 여부를 읽기 전용으로 점검한다.
- `CompositionFactory.withExportQuality`: 선택 해상도 `Presentation.createForShortSide`와 선택 FPS `FrameDropEffect`를 Media3 비디오 효과에 적용한다.
- `VideoExporter`: 수동 옵션은 고속 복사/네이티브 재인코딩 경로를 건너뛰고 Media3에서 지정 비트레이트로 인코딩한다.
- 저장 전에 임시 출력 영상에서 해상도와 선택된 경우 프레임 타임스탬프의 FPS를 검증하고, 불일치하면 갤러리에 공개하지 않는다.
- 기존 Media3 frame guard의 정상 프레임 수 검증은 유지하되, 사용자가 FPS를 명시적으로 낮춘 경우에만 고의적 프레임 삭제를 허용하고 실제 FPS를 별도로 검증한다.
