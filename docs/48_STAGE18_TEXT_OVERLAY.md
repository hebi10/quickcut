# QuickCut 18단계 — 영상 텍스트 오버레이 구현·검증 계획

기준: 2026-11-08 / QuickCut Android 0.4.20 / 기존 main 13단계 안정 버전  
원본 기획: https://docs.google.com/document/d/1fTi_fx0g6CF6SwpRKjrlYdbK9Pp9oAqmSg6To4GkhfI/edit

## 구현 범위

- 기존 상세 편집 **자르기·분할·삭제·순서·음소거**를 유지하며 새 **텍스트** 도구 진입을 추가.
- 하나의 클립에 텍스트 레이어 최대 5개, 클립 내 시작·종료(최소 0.1초), 영상에서 직접 드래그하는 위치(정규화 좌표 0.14~0.86), 글자 크기 60~170%, 흰색/검정/보라/노랑, 왼쪽/가운데/오른쪽 정렬, 텍스트 배경.
- 텍스트 80자 이내, 최대 3줄·한 줄 32자. 비어 있거나 유효하지 않은 레이어는 적용할 수 없고 빈 레이어를 임의 저장하지 않는다.
- 프리뷰에는 기존 ComposePlayer/Media3 CompositionFactory와 동일한 `OverlayEffect` 적용. **텍스트는 재생 중 지정한 시간 범위에만 나타나며**, 클립별 로컬 시간으로 관리한다.
- 효과 시간은 Media3의 `TimestampWrapper`로 지정. 빈 `TextOverlay`를 렌더링하는 방식과 달리 표시 시간 외에는 비디오 효과 자체를 우회한다.
- 색상/글자/정렬은 Android SpannableString 및 `StaticOverlaySettings`에서 정의. 위치는 Media3 NDC로 변환해 프리뷰와 MP4에 동일 효과를 적용한다.
- 화면에서 텍스트 입력, 다중 레이어 선택·삭제, 크기·색상·정렬, 위치·시간 변경, 실제 영상 재생·탐색, 고정 하단 취소·적용.
- 원본 영상은 변경하지 않는다. 기존 고속 복사/네이티브 부분 처리 경로는 **텍스트가 없는 클립에서 그대로 유지**한다. 텍스트가 있으면 저장 전 **재인코딩 승인**을 요구하고 Media3 변환 결과를 정상 검증·갤러리 게시한다.
- `VideoClip.textLayers` 선택적 데이터와 `EditorSessionStore` 버전 3 JSON을 통해 기존 프로젝트/세션에 대해 빈 레이어 기본값을 적용한다. 프로젝트 저장·복구·Undo/Redo는 현재 흐름 재사용.
- 클립 길이 트림/분할 시 텍스트 표시 시각은 원본 위치 기준으로 안전하게 이동·클램프하며, 범위 밖 레이어는 제거한다.
- 자막 추출/음성인식/텍스트 애니메이션은 이번 범위 아님. 동작하지 않는 탭이나 버튼은 표시하지 않는다.

## 주요 변경 파일

- `editor/TextLayer.kt`: 텍스트 스타일·위치·시간·유효성 검사, 트림/분할 정책
- `editor/EditTimeline.kt`: 클립별 텍스트 레이어 및 편집 이력 연결
- `editor/EditorSessionStore.kt`: 기존 프로젝트와 호환되는 선택적 JSON 저장
- `editor/EditorViewModel.kt`: 단일 undo/redo/자동저장 변경
- `media/TextOverlayEffects.kt`: Media3 문자 렌더러, 타이밍 효과와 화면 좌표
- `media/CompositionFactory.kt`: 프리뷰·출력 공용 효과 적용
- `media/ExportPlanner.kt`, `VideoExporter.kt`: 원본 빠른 복사와 텍스트 변환 분리, 승인 및 복구 유지
- `ui/TextEditorScreen.kt`: 반응형 텍스트 편집 화면
- `ui/EditorScreen.kt`: 기존 도구 유지 + 텍스트 진입
- `app/build.gradle.kts`: 프로젝트와 일치하는 Media3 effect artifact

## 병합·배포 게이트

- 이 브랜치는 15~17단계 PR과 충돌하지 않도록 **독립된 main 기준**으로 개발.
- 동일한 HEAD SHA의 전체 CI 성공, 화면 캡처, 실제 MP4 결과 검증 전에는 Draft로 유지하고 main 병합 금지.
- 15·16·17단계의 검증과 병합 여부에 따라 통합 PR 작성 및 합성/코덱 테스트 재실행.
- Google Play 내부/비공개 테스트 배포는 확인되지 않은 코드로 진행하지 않음. 비공개 테스트 게시에는 별도 명시적 요청 필요.

**현재 상태:** 18단계 구현 초안 및 테스트 정의. 실제 CI, Android 캡처와 결과 검증 전에는 완료로 판단하지 않는다.
