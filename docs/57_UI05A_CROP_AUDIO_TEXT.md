# UI-05-A — 크롭·오디오·텍스트 정밀 편집 리디자인

- 기준: 2026-11-12
- 의존성: PR #55 (3-A) → PR #56 (4-A) → PR #57 (4-B) → 본 PR (5-A)
- 디자인 기준: https://docs.google.com/document/d/1hyNminChkLsX3MHes3xM_m4KuuHTHD1gC0K8O5UnRCo/edit
- 기술: 기존 Android Kotlin/Jetpack Compose, Media3 및 Native SmartCut 편집/저장 엔진 유지.

## 변경 범위

### 크롭
- 기존 미디어 픽셀/좌표 매핑과 드래그·핀치 확대 로직은 보존.
- 검정 프레임 위 크롭 영역 안내 제목을 추가하고, 비율 버튼을 고정 86dp 규격으로 정렬해 비율 옵션을 가로 스크롤할 수 있도록 함.
- 선택 중인 가로/세로 비율을 실제 `CropRegion.width/height` 값으로 표시.
- 400dp 미만 또는 150% 이상 글꼴에서 축소·확대 및 좌·우 이동 버튼을 두 행으로 나눠 최소 48dp 터치를 확보하고, 넓은 화면은 기존 한 행 유지.
- 초기화·자유 비율·저장 전 재인코딩 동의 및 원본 보호는 변경하지 않음.

### 오디오
- 원래 플레이어 미리보기와 적용 예상 파형을 구분하는 제목 표시.
- 설정 비교: 선택 클립의 기존 볼륨/페이드/음소거 상태 vs 현재 입력값을 보여 주되, 비동기 미리보기 엔진의 실제 적용 성공을 주장하지 않음.
- 음량 0~100%, 0.5초 단위 페이드, 음소거·원본 파형, 미리보기와 적용 동작, Media3 gain envelope를 수정하지 않음.
- 파형을 읽지 못한 상태도 기존 안내·조절 동작 유지.

### 텍스트
- 선택된 레이어 순서/전체 개수를 명시하고, 색상·정렬·레이어 선택 버튼의 선택 상태를 접근성 semantics로 전달.
- 레이어 미추가 상태에 실제 안내문 제공.
- 시간 입력은 400dp 미만 또는 글꼴 150% 이상에서 세로로, 넓은 화면에서는 가로로 배치.
- 기존 `text-start-seconds`/`text-end-seconds` 태그, 입력 제한, 범위 유효성, 텍스트 위치 드래그, 키보드/적용 버튼, 기존 미리보기/Media3 출력 동작 유지.
- 빈 텍스트 레이어는 기존 `TextLayerPolicy.isValid`에서 계속 차단하고, 레이어를 모두 제거한 후 비어 있는 배열 적용은 기존 삭제 동작을 보존.

## 검증

- 기존 `Stage16CropScreensInstrumentedTest` 2개: 360dp 세로·정사각·자유 비율, 860dp/160% 폰트, 크롭 영역·컨트롤 확인.
- 기존 `Stage17AudioScreensInstrumentedTest` 2개: 100% 기본, 45%·페이드, 음소거, 태블릿/160%와 오디오 조정값 비교 패널 확인.
- 기존 `Stage18TextEditorScreensInstrumentedTest` 2개: 빈 레이어·유효하지 않은 문구 차단·텍스트 선택·색상/시간·키보드·860dp/160% 입력 배치 확인.
- 해당 12장의 실제 Android PNG (`stage16_crop_*.png` 4, `stage17_audio_*.png` 4, `stage18_text_*.png` 4)은 기존 `android-instrumentation-check.sh`/Stage20 증거 게이트에서 필수 PNG 무결성·XML 테스트 성공 검사. 테스트 개수 추가 없음.
- 기존 Stage19 크롭+오디오+텍스트 조합 MP4 출력과 Stage20 기존 프로젝트·원본 SHA 안전성 검증을 그대로 실행. CI 실행 전 통과 주장 금지.
- 선행 PR #56 에뮬레이터 실패 로그에서 정확히 확인된 테스트 오류 두 건(Compose 병합/비병합 태그 트리 및 UI 스크롤 위치)을 #56·#57·본 브랜치의 기존 테스트에 적용. 기존 앱 동작이나 테스트 범위를 줄이지 않음.

1. #55 → #56 → #57 선행 PR 모두 정확한 최신 HEAD의 build/Lint/API 29·35·36 전체 통과 및 실제 화면 검수 후 순차 `main` 병합.
2. 본 PR을 그때 최신 `main`으로 base 변경하고 Android 빌드·단위/Lint/APK/AAB, API29 292개 및 API35/36 전수, 12개 UI 캡처·MP4 실출력·원본 보호 검증을 새 SHA에서 재실행.
