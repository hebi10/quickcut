# 0.4.10 안정성·고속 저장 보완

사용자가 승인한 전체 피드백을 구현한다. 새 라이브러리 없이 기존 Kotlin/Compose/Rust 구조와 다크 UI를 유지한다.

1. 날짜 유지용 임시 파일도 소유 파일 규칙에 따라 정리한다. 단일 저장의 pending URI와 출력 검증 조건을 원자적으로 기록하고, 프로세스 재시작 시 완료 파일을 복구하거나 미완성 파일을 정리한다. 원본 삭제 동의는 복구하지 않는다.
2. 네이티브 원본 분석을 변경 감지·메모리 상한이 있는 캐시로 재사용한다. FD 번호를 파일 식별자로 사용하지 않는다. 취소된/실패한 분석은 보관하지 않는다. 분석 진행률과 단계를 표시한다.
3. 추천 경계는 마이크로초로 보존한다. 사용자 편집은 기존 밀리초 입력을 유지하되 정밀 경계가 묵시적으로 바뀌지 않게 한다. 인접 후보 검증에 실패하면 더 안쪽의 안전 후보를 탐색한다. 삭제 방향·최소 0.1초·영상 복사 전용 검증은 유지한다.
4. 요청/추천 경계의 실제 프레임을 비교하고 각 경계 주변 및 연결부를 짧게 재생할 수 있게 한다. 미리보기 실패가 저장 동의로 처리되면 안 된다.
5. 일괄 저장에서 파일별 정확한 위치/추천 위치/제외 선택을 제공한다. 변경한 설정·파일 목록·재시도에서는 이전 동의를 재사용하지 않는다. 정확한 위치 선택에는 기존 자동 저장 정책을, 추천 선택에는 FAST_ONLY를 적용한다.
6. 오류 단계, 앱/기기 정보, 영상 형식, 처리 시간, 저장 공간을 기기 내부에 기록하고 사용자가 확인·복사할 수 있게 한다. 원본 경로·URI·파일명·영상 내용·인증 정보를 포함하지 않으며 네트워크 전송 기능은 추가하지 않는다.
7. 장시간/오디오/고해상도 검증을 보강하고 실기기 확인 절차를 제공한다. 접근하지 못한 Fold8 및 사용자 3시간 원본의 오류 해결을 주장하지 않는다.
8. 버전 0.4.10/versionCode 15로 검사한 변경을 main에 통합하고 README의 오래된 상태 설명을 정리한다. 기존 배포 인증서로 APK와 대응 소스를 배포한다.

## 공통 인터페이스

- `PreciseClipRange(startUs: Long, endUs: Long)`와 `VideoClip.preciseRange: PreciseClipRange?`, `startUs`, `endUs`, `durationUs`, `withRangeUs(startUs, endUs)`를 사용한다. `startMs`는 내림, `endMs`는 올림으로 표시 좌표를 유지하며 실제 저장은 us를 사용한다. 명시적 시간 편집은 정밀 범위를 갱신하거나 지운다.
- `FastCutSuggestion.createUs(requested, rangesUs)`는 실제 us 좌표로 안쪽 이동만 허용한다. 기존 `create(...rangesMs)`는 호환을 유지한다.
- `NativeSmartCutTrimmer.suggestCopyRangesUs(context, timeline, onProgress: (Int?) -> Unit = {})`는 us 쌍을 반환한다. `ExportPlanner.analyze`에도 기본값이 있는 `onProgress`를 추가한다.
- `FastCutPreview(suggestion: FastCutSuggestion)`는 단일·일괄 확인 화면에서 재사용할 Compose 컴포넌트이다.

## 검증 기준

중단·권한 거부·정리 실패·공개 직후 프로세스 종료, 원본 교체/수정 및 FD 재사용, 밀리초 미만 경계·동일 표시 시각·짧은 클립, 일괄 선택 후 설정 변경, 미리보기 디코더 미지원 조건을 포함한다. 정상 출력·원본 유지·저장 동의와 실제 시간 범위가 일치해야 한다.
