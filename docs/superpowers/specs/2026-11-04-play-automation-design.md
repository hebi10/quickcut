# QuickCut 테스트 배포 자동화

GitHub Actions에서 현재 main 소스의 기존 빌드·기기 검증이 성공한 경우에만 동일 업로드 키로 APK와 AAB를 생성하고 Google Play 테스트 트랙을 업데이트한다. 기본 자동 배포는 기존 비공개 트랙이며, 수동 실행에서는 내부·비공개·두 트랙을 선택할 수 있다. 프로덕션 배포는 허용하지 않는다.

기존 APK 공개 릴리스의 불변 태그와 검증 절차를 유지한다. 별도 Play 워크플로가 같은 소스·검증 게이트, 정확한 네이티브 캐시, 키 인증서 고정, 소스 패키지·체크섬을 재사용한다. APK/AAB는 커밋된 버전명과 versionCode를 함께 사용하며 새 버전은 versionCode를 증가시킨다.

패키지는 com.hebi.quickcut, 업로드 인증서 SHA256은 64d8bb097fa2fb39401c5a01026e6fc8d36f5136d5684732c1f310e6affb2d67이다. 네 개의 기존 QUICKCUT 서명 시크릿을 재사용한다. Google 인증은 공식 auth Action의 WIF를 우선하며, 기존 서비스계정 JSON이 이미 제공된 경우에만 선택적으로 재사용한다. 자격 증명이나 토큰을 로그·산출물·저장소에 포함하지 않는다.

Play 편집은 직렬화한다. 실제 tracks.list에서 내부 트랙 ID와 설정한 기존 비공개 트랙을 검증하고 프로덕션·오픈 테스트를 거부한다. 이미 목표 트랙에 동일 버전이 있으면 재실행은 성공한 무변경으로 끝낸다. 이미 업로드된 versionCode는 새 바이너리로 덮어쓰지 않고 기존 버전 승격만 허용한다. 업로드·검증·커밋 실패 시 성공으로 표시하지 않으며 진행 중인 기존 심사를 취소하지 않는다.

의미 있는 로컬 테스트는 신뢰 게이트, 버전·서명 검증, 트랙 제한, 재시도·중복 버전, API 실패와 심사 충돌을 다룬다. 실제 연결 상태와 Actions 결과를 별도로 확인하고 인증 정보가 부족하면 배포 완료로 주장하지 않는다. 앱 UI, 편집 엔진, 기존 테스터 목록과 다른 앱 설정은 변경하지 않는다.
